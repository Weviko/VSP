# 11. 추가 필요 기능 — 갭 분석

> 작성: 2026-09-11
> 계기: "한국 문체부의 행정·운영 시스템을 그대로 이식한다"는 방침 확정
> 목적: 플랫폼 본 제작에 들어가기 전, **지금 빠져 있는 것**을 미리 식별한다

---

## 0. 관점 전환 — 무엇이 달라졌나

지금까지 조사·구현은 **대한체육회(체육 단체) 레벨**이었다.
그런데 협의 상대가 **베트남 문화체육관광부(정부 부처)**라면 한 층 위의 시스템이 필요하다.

```
[지금까지 구현한 범위]              [새로 필요한 범위]

                                  문화체육관광부 (정부 부처)
                                    ├─ 온나라시스템  (공문·결재·문서유통)
                                    ├─ e나라도움     (보조금 전 주기)
                                    ├─ dBrain        (예산·회계)
                                    └─ 나라장터      (조달·계약)
                                          ↕ 공문 유통
  대한체육회 ────────────────────────────┘
    ├─ 스포츠지원포털  ✅ 구현
    ├─ 등록·대회·결재  ✅ 구현
    └─ 경영공시        ✅ 구현
          ↕
  회원종목단체 · 시도체육회  ✅ 구현
```

> **핵심**: 우리는 "체육회가 쓰는 시스템"을 만들었다.
> 문체부가 쓰려면 **"부처가 체육회를 관리·감독하는 시스템"**이 추가로 필요하다.
> 그 둘은 같은 플랫폼 안에 있어야 하며, 그것이 한국에는 없는 통합이다.

## 1. 한국 정부 행정 시스템 구조 (조사 결과)

### 1-1. 온나라시스템 — 정부 표준 전자문서

| 항목 | 내용 |
|---|---|
| 운영 | 행정안전부. 중앙행정기관·지자체 공통 |
| 범위 | 문서결재 + 지식관리 + 메일 + 영상회의 |
| 핵심 | **기관 간 문서유통 표준** — 부처↔기관 공문 송수신 |
| 절차 | 기안 → (타 부서) **합의** → 결재 → 시행 → 상대 기관 **접수** → **열람범위 지정** |
| 포맷 | ODT·PDF 국제표준 |

> **우리에게 없는 것**: 기관 **간** 공문 유통. 지금은 조직 **내부** 결재만 있다.
> 문체부 → 체육회 → 협회로 공문이 내려가고 보고가 올라가는 경로가 없다.

### 1-2. e나라도움 — 보조금 전 주기

```
공모등록 → 공모신청 → 선정 → 사업등록(계좌·추진계획·집행계획)
→ 교부신청 → 교부결정 → [계약관리] → 집행관리 → 정산관리 → 정보공시
                                   ↑
                    내역사업 단위로 중앙→지자체→민간→최종 집행까지 추적
                    + 부정수급·중복수급 검증
```

> **우리에게 없는 것**: 보조금 사이클 전체. 지금은 수납(받는 돈)만 있고
> **교부(주는 돈)와 정산·검사**가 없다. 정부 입장에서 가장 중요한 부분이다.

### 1-3. 문체부 체육 조직 (업무 범위의 근거)

| 조직 | 부서 |
|---|---|
| 체육국 | 체육정책과 · 체육진흥과 · 스포츠산업과 · 스포츠인권복지과 |
| 체육협력관 | 국제체육과 · 장애인체육과 · 스포츠유산팀 |

> 이 부서 목록이 곧 **플랫폼이 다뤄야 할 업무 영역**이다.
> 스포츠산업·장애인체육·스포츠인권·스포츠유산은 지금 우리에게 전혀 없다.

## 3. 우선순위 — 무엇을 먼저 만들 것인가

판단 기준 세 가지:
1. **미팅에서 나올 확률** — 문체부가 물을 것
2. **없으면 다른 것이 막히는가** — 선행 의존성
3. **나중에 넣기 어려운가** — 구조에 관련된 것

### 1순위 — 본 제작 착수와 동시에 (지금 없으면 다른 일이 막힌다)

| # | 기능 | 이유 |
|---|---|---|
| **D1** | **서식 편집기(GUI)** | 체육회 서식을 받아도 **넣을 화면이 없다.** 개발자가 SQL로 넣으면 "설정으로 대응" 전략이 무너진다 |
| **D2** | **결재선 편집기(GUI)** | 위와 동일. 종목별로 다른 결재선을 화면에서 만들 수 있어야 한다 |
| **B1~B5** | **보조금 전 주기** | 문체부 미팅의 핵심 주제. 공모→교부→집행→정산→검사 |
| **A1~A3** | **기관 간 공문 유통** | 문체부↔체육회↔협회 경로. 부처가 쓰려면 필수 |
| **D6~D8** | 파일 저장 · PDF · 엑셀 | 모든 업무가 첨부·출력·이관을 쓴다 |
| **D5** | 알림 발송(Zalo/SMS) | 결재·마감 알림이 없으면 시스템을 안 본다 |

## 5. 문체부 미팅에서 확인할 것 (신규)

기존 §13 협조 요청에 더해, 부처 레벨 시스템 때문에 새로 생긴 질문이다.

| # | 질문 | 왜 중요한가 |
|---|---|---|
| 1 | **베트남 정부의 전자문서시스템이 이미 있는가?** (한국 온나라 같은) | 있으면 연동, 없으면 우리가 만든다. **설계가 완전히 갈린다** |
| 2 | **공문이 기관 간에 전자로 오가는가, 종이인가?** | 문서유통 구현 범위 |
| 3 | **국가 보조금 관리 시스템이 있는가?** (한국 e나라도움 같은) | 있으면 연동, 없으면 우리가 만든다 |
| 4 | 체육 예산이 어떤 경로로 협회에 내려가는가? | 보조금 모듈 설계의 근간 |
| 5 | 보조금 정산·검사는 누가 하는가? | 결재선 설계 |
| 6 | **위원회가 몇 개 있고 무엇을 심의하는가?** | 의사결정 구조 |
| 7 | 문체부 체육 담당 조직도 (한국의 체육국·체육협력관에 해당) | 업무 범위 확정 |
| 8 | 장애인체육을 같은 플랫폼에 담는가, 분리하는가? | 범위 결정 |
| 9 | 스포츠산업(용품·시설업) 등록 업무가 있는가? | 범위 결정 |
| 10 | 정보공개청구·민원 처리 의무가 있는가? | 대외 기능 |
| 11 | 감사 체계는 어떻게 되는가? | 감사 모듈 |
| 12 | 국가대표 선발·훈련을 시스템으로 관리할 의향이 있는가? | 체육회 본업 |
