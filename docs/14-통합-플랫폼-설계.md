# 14. 통합 플랫폼 설계 — 행정 전산망 + 스포츠 웹을 하나로

> 작성 2026-09-14 · 선행: 04(청사진) · 09(IA) · 13(구조 비교)
> 목표: **한국의 대한체육회·문체부 행정 시스템 + 네이버 스포츠를, 하나의 데이터 위에 얹은 베트남 전문 체육 플랫폼.**
> 이 문서는 2026-09-14 로그인 세션으로 네이버 스포츠와 대한체육회 g1 포털을 직접 열람해 확인한 구조를 근거로 한다.

---

## 0. 한 줄 정리

VSP 는 **두 얼굴, 하나의 데이터**다.
- **안쪽(행정 전산망)** = 대한체육회 g1 + 문체부 온나라·e나라도움 계열 → `apps/platform`
- **바깥쪽(스포츠 웹)** = 네이버 스포츠 계열 → `apps/portal`
- 안쪽에서 입력한 데이터가 바깥쪽에 자동으로 나타난다. 이것이 이 플랫폼의 핵심이며, 두 시스템을 잇는 것이 이미 만든 `pub` 공개 데이터 계층이다.

## 1. 직접 확인한 두 원본 (2026-09-14)

### 1-1. 네이버 스포츠 — 바깥 얼굴의 원본

| 층 | 구성 |
|---|---|
| 유틸리티 | NAVER · 스포츠 · 뉴스 · 엔터 / 내 계정·알림·메일·전체메뉴 |
| **종목 탭** | 홈 · 야구 · 해외야구 · 축구 · 해외축구 · 농구 · 배구 · N골프 · AG·일반 · e스포츠 · 아웃도어 · **MY팀 설정** |
| 기능 메뉴 | 오늘의 경기 · 승부예측 · 연재 · 이슈톡 · 대학스포츠 · 랭킹 |
| **종목 내부** | 뉴스 · 영상 · 일정 · 순위 · 포토 → 그 아래 리그·대회 필터 |

- 경기 카드: `[국기]팀 — 점수/상태 — 팀[국기]` + 응원/영상 배지. (전 종목 공통, 오늘의 경기)
- 순위(종목 안 리그 순위) ≠ 랭킹(전역 인기 뉴스). MY팀으로 개인화.

### 1-2. 대한체육회 g1 — 안쪽 얼굴의 원본(등록·증명)

> 내 생애주기 · 경기인 등록 · 증명서 발급 · 등록현황 · S콘텐츠 · 대회정보 · 이용안내
> \+ 체육인 전자지갑 · 전자증명서 서비스

### 1-3. 문체부 계열(문서 13에서 조사) — 안쪽 얼굴의 행정

- 온나라시스템(기관 간 공문 유통) · e나라도움(보조금 전 주기) · 국가 보고 시스템.
- 베트남 대응: 국가 공문축·공공서비스 포털(VNeID)·국가 보고 시스템이 **국가기관 층에는 이미 존재**. VSP 는 국가기관이 아닌 **체육단체 층**을 담당하고 경계에서 연동(문서 13 §3).

## 2. 두 원본을 VSP 의 두 얼굴에 매핑

### 2-1. 바깥 얼굴 `apps/portal` ← 네이버 스포츠

| 네이버 | VSP 현재 | 할 일 |
|---|---|---|
| 종목 탭 1단 | ✅ 1단 배치 완료 | 유지 |
| 종목 내부: 뉴스·영상·일정·순위·포토 | 기능이 **전역**(일정/결과/순위/선수/뉴스), 종목은 필터 | **종목 안으로 기능을 넣는 구조로 전환 검토** (§4-A) |
| 오늘의 경기(경기 카드+응원/영상) | 대회·경기 데이터는 있으나 "오늘의 경기" 화면 없음 | 경기 카드 화면 추가 (`sport.match` 활용) |
| 순위(리그) / 랭킹(인기) 분리 | 랭킹 자리표시만 | 리그 순위(`ranking_snapshot`) + 뉴스 인기 분리 |
| MY팀 개인화 | 없음 | 회원 서비스(`/my`)와 연결해 "내 종목·내 팀" |
| 영상/포토 | 없음 | 대회 하이라이트·사진 (콘텐츠 단계) |

### 2-2. 안쪽 얼굴 `apps/platform` ← g1 + 문체부

| 원본 | VSP 현재 | 상태 |
|---|---|---|
| 경기인 등록(선수·지도자·심판) | 동적 서식 + 2단계 결재 | ✅ |
| 내 생애주기(신청·활동·교육 이력) | 회원 서비스 `/my` | ✅ |
| 증명서 발급·진위확인 | certificate + `pub.verify_certificate` | ✅ |
| 등록현황(선수통합검색·경영공시) | 공개 선수검색·단체 공시 | ✅ |
| 대회정보(주간·월간·연간) | 대회 일정 3단 보기 | ✅ |
| 온나라(기관 간 공문) | dispatch/합의/접수/대장 | ✅ (문체부 연동 방식 미확정) |
| e나라도움(보조금 전 주기) | grant 모듈 | ✅ |
| **체육인 전자지갑** | 없음 | **신규 검토** (§4-B) |
| 감사·위원회·도핑·징계 | 미구현 | 미팅 후 (문서 11) |

**결론: 안쪽은 골격이 거의 서 있고, 바깥쪽은 네이버식으로 다듬을 여지가 크다.**

## 3. 베트남 현지화 세팅

### 3-1. 종목 탭 — 베트남 인기 종목 순
네이버가 야구를 앞세우듯, 베트남은 **축구(Bóng đá)를 최상위**에 둔다. 권장 초기 순서:
> 홈 · 축구 · 배구(Bóng chuyền) · 격투기(태권도·보비남·무에타이) · 육상(Điền kinh) · 수영(Bơi) · e스포츠 · 전체 종목

- 종목 목록은 DB(`sport.sport.sort_order`)에서 오므로 코드 수정 없이 순서·추가 가능.
- 보비남(Vovinam)·다카오(Đá cầu) 같은 **베트남 고유 종목**을 1급 종목으로. 네이버에 없는, VSP 만의 강점.

### 3-2. 언어·표기
- 기본 vi, 보조 en/ko. 종목명·단체명은 `name_i18n`.
- 경기 카드의 국기·국가명은 국제대회(SEA Games·ASIAD)에서 그대로 쓸 수 있게 ISO 국가코드 기반.

### 3-3. 행정 경계 (문서 13 재확인)
- 연맹 내부·연맹↔지방·연맹↔클럽 공문: **VSP 전담.**
- 연맹↔문체부, 대회 개최 신청, 회원 로그인(VNeID): **국가 시스템과 연동.** 중복 구현 금지.

### 3-4. 개인화·계정
- 로그인은 전화 OTP(현재) → **VNeID 연동 검토**(국민이 이미 가진 신원).
- MY팀 = 팬 개인화(바깥). 내 생애주기 = 선수·지도자 본인 이력(안쪽 `/my`). 같은 계정, 다른 화면.

## 4. 이번 조사로 새로 잡힌 항목

### A. 바깥 얼굴을 "종목 우선" 구조로 (검토)
네이버는 *종목을 먼저 고르고 그 안에서 일정·순위·기록*을 본다. VSP 는 기능이 전역이다.
- **추천**: 종목 페이지(`/[sportCode]`) 안에 뉴스·일정·순위·기록·영상 탭을 넣는다. 전역 일정/결과/순위 페이지는 "전 종목 모아보기"로 남긴다(둘 다 제공).
- **위험**: 지금 IA 를 바꾸면 이미 만든 공개 화면 구조를 손봐야 한다. **IT팀 디자인 단계에서** 하는 것이 맞다. 지금은 근거만 기록하고 코드는 두지 않는다.

### B. 체육인 전자지갑 (검토)
g1 에 있는 기능. 선수의 자격증·증명서·경력을 한 곳에 모아 본인이 관리·제출. 회원 서비스(`/my`)의 자연스러운 확장.
- **추천**: 증명서 모듈이 이미 있으므로, `/my` 에 "내 증명서·자격" 지갑을 얹는다. 미팅 후 우선순위.
- **위험**: 전자증명서의 법적 효력은 베트남 전자서명·VNeID 정책에 달렸다. 정책 확인 전에는 "보관·조회"까지만.

### C. 오늘의 경기 화면
경기 카드(응원·영상 배지)는 대중 유입의 핵심 화면인데 아직 없다. `sport.match`·`event`·`event_result` 로 만들 수 있다. 콘텐츠(영상)는 나중이라도 카드 자체는 초기에 넣을 값어치가 있다.

## 5-B. 네이버 스포츠가 "어떻게 움직이나" — 동작 검토 (2026-09-15)

구조(정지 상태)에 더해 **화면이 실제로 어떻게 도는지**를 로그인 세션으로 확인했다.

### 경기 흐름 (대중 유입의 핵심)
- **경기 카드의 버튼이 상태에 따라 바뀐다**: 예정 → **응원**, 진행 중 → **문자(중계)**, 종료 → **기록**. 누르면 그 상태에 맞는 상세 탭으로 바로 간다.
- 경기 상세 URL: `/game/{경기ID}/{relay|record|cheer}`. 경기ID에 날짜·팀·대회가 인코딩됨 (예: `20260915SFSL0`).
- **경기 상세 = 하나의 작은 앱**: 탭 6개 — 응원 · 라인업 · 중계 · 뉴스 · 영상 · 기록.
  - 점수 헤더(팀 로고·큰 점수·상태·승리투수) + **종목별 기록표**(야구는 이닝별 R·H·E·B) + **경기 한 줄 평(팬 코멘트)** + 같은 날 다른 경기로 가로 전환 + 네이티브 광고.
- **실시간 갱신 확인**: 진행 중 경기가 "8회초 7:6"처럼 이닝·점수가 살아서 바뀐다.

### 순위·기록 (종목 안 `순위` 탭)
- 하위 4종: **팀 순위 · 팀 기록 · 타자 기록 · 투수 기록** (종목마다 지표가 다름).
- 필터: 리그(KBO/퓨처스) · 시즌(정규시즌 등) · 연도.
- 팀 순위 표: 순위·승률·게임차·경기·승·패·무.

### e스포츠는 **별도 서비스로 분리돼 있다** (통합 구상에 직접 영향)
- 네이버 스포츠의 `e스포츠` 탭은 스포츠 사이트를 **떠나** `game.naver.com/esports` 로 간다.
- 구조가 다르다: **게임 타이틀이 최상위 선택자**(LoL·PUBG·발로란트·오버워치, 각 LIVE 배지) → 내부 메뉴 **홈·커뮤니티·경기·뉴스·일정·영상·순위·승부예측·라운지**.
- 전통 종목에 없는 층이 붙는다: **커뮤니티·라운지(멤버십)**, 그리고 중계 플랫폼 **치지직**과 밀착.
- **시사점**: 네이버조차 e스포츠를 스포츠 사이트에 합치지 않고 따로 뒀다. VSP 가 "한 플랫폼"에 담으려면 **데이터 모델로는 한 종목**으로 넣되(문서 §4·아래), 공개 화면에서는 e스포츠에 **타이틀-우선 내비 · 커뮤니티/라운지 · 영상/중계 비중**을 더해야 한다. 전통 종목 화면을 그대로 쓰면 안 된다.

### 콘텐츠·개인화 메뉴 (2026-09-15 클릭 흐름까지 확인)
- **승부예측 = 계정 기반 예측 게임.** 3개 탭(오늘의 경기·나의 예측·랭킹) + 날짜(7일)·종목 필터. 각 경기에 **집단 예측 비율(%)** 표시, 맞히면 **누적 스코어** 획득, **주간 랭킹** 도전, 언더독 성공 시 추가 점수. 현금 없음(포인트 게이미피케이션).
- **MY팀 = 팀 구독(팔로우).** 탭 2개(구독 팀·구독 혜택). 리그별 선택(추천·KBO·MLB·K리그1/2·PL·라리가·분데스·세리에A·리그1·MLS·KBL·WKBL) → 팀마다 **구독자 수·급상승 배지** → `+`로 구독. 구독하면 그 팀 중심으로 재구성.
- **이슈톡 = 커뮤니티 피드**(공지·팬 글). **연재 = 편집 칼럼 시리즈.** **대학스포츠 = 시즌형 섹션.**
- **동작 방식**: 모바일 네이버 스포츠는 단일 페이지 앱(SPA)이라 연재·대학스포츠·MY팀 설정은 **외부 주소로 직접 접근 불가**, 앱 안에서 눌러야 열린다. **실시간 데이터가 밀려온다**(진행 경기 이닝·점수가 새로고침 없이 갱신 — 8회초 7:6 → 8회말 8:7 로 살아 움직임 확인).

### 승부예측의 함의 (정부 플랫폼 주의)
- 승부예측(현금 없는 예측 게임)은 대중 참여를 크게 끌지만 **구조가 스포츠 베팅과 인접**하다. VSP 는 정부 공식 지정을 노리므로:
  - 넣더라도 **현금·환금 요소 없이 포인트/명예 랭킹만**, 그리고 **베팅과 명확히 분리**.
  - 기존 규칙대로 **대외 문서·화면에 베팅을 언급하지 않는다**. 승부예측을 베팅의 우회로처럼 보이게 해서는 안 된다.
  - 초기 범위에서는 보류를 권한다(미팅 후 판단).

### VSP 에 주는 구체 반영
1. **경기 상세를 상태 기반 탭으로**: 예정/진행/종료에 따라 응원·중계·기록 탭. **[구현 완료 2026-09-15]** 오늘의 경기(`/scoreboard`, 상태별 버튼) + 경기 상세(`/matches/[id]`, 6탭·점수헤더·기록표) + 종목별 기록표는 `sport.match.box_score`(JSONB)로 흡수(마이그레이션 009). 공개뷰 `pub.match` + `getMatch`/`listScoreboard`, 포털 역할 런타임 검증(test:public). 중계·뉴스·영상 탭은 콘텐츠 모듈 연결 전 자리표시.
2. **순위 탭의 4종 분화**(팀순위/팀기록/개인기록) + 리그·시즌 필터. **[구현 완료 2026-09-15]** 유연한 순위판 모델(`sport.standing_board`+`standing_entry`, 컬럼/셀 JSONB, 마이그레이션 010) — 종목마다 지표가 달라도 마이그레이션 불필요. 공개뷰 `pub.standing_board`/`pub.standing_entry`(개인기록 미성년 이름 자동 마스킹) + `listStandingBoards`/`getStandings`, 포털 `/rankings`(종목→리그→순위판 탭→표). 런타임 검증(test:public).
3. **경기 한 줄 평(팬 코멘트)** — 대중 참여. 우리 `cheer`/`poll` 에 코멘트형 추가 검토.
4. **e스포츠**: §4 데이터 모델은 그대로, 공개 화면만 타이틀-우선 + 커뮤니티/중계 강화.
5. **MY팀형 팀 구독**: 회원이 종목·팀을 구독해 개인화. 구독자 수는 단체·선수 인기 지표로도 쓰인다 — 후원 중개(문서 06)와 연결 가능. **[구현 완료 2026-09-16]** `core.subscription`(다형 SPORT/ORG, 마이그레이션 011) + core-admin `subscribe/unsubscribe/listSubscriptions`. 공개는 집계만(`pub.subscriber_count`, 누가 구독했는지 비공개). 플랫폼 `/my` 관심 종목 관리(구독/해지, 서버 액션 requireMember), 포털 종목 허브에 구독자 수 표시. 런타임 검증(test:public).
6. **승부예측은 정부 플랫폼 특성상 신중히**(위 함의). 실시간 데이터 갱신은 오프라인 입력 후 동기화(`match.synced_at`)와 맞물려 설계.

## 6. 조사 방법과 한계

- 네이버 스포츠·g1 은 **대표 계정 로그인 세션**으로 **사람이 보는 속도로 소량만** 열람했다(메인·오늘의경기·랭킹·야구·축구·배구·g1 안내). 대량 수집·저장·재배포 없음. 근거: `~/.claude/CLAUDE.md` §3 "대신 보기".
- 모바일 네이버는 화면 안에서 바뀌는 방식(SPA)이라, 안정적으로 드러나는 PC 버전과 화면 캡처를 함께 썼다.
- g1 메인(`/main/index.do`)은 자동 접근이 차단돼 공개 안내 페이지로 구조를 확인했다.
- 다른 종목(농구·골프·e스포츠 등)은 야구·축구·배구와 같은 패턴이라 전수로 훑지 않았다.
- 동작 검토(2026-09-15)는 경기 흐름·순위·e스포츠 연결·경기 상세까지 직접 확인했다. 승부예측·연재·이슈톡·대학스포츠·MY팀 설정 흐름은 SPA 라 존재·위치만 확인했고 세부 클릭 동작은 다음 차례로 남겼다.
