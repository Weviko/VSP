# 22. 결제 연동 준비 (후원·등록비 온라인 결제)

> 대상: 사업 주체·IT팀·법무. 후원(스폰서)·등록비의 **온라인 결제(VNPay 등)** 실연동을 위한 선행조건과 절차.
> 현재 상태: 결제는 **어댑터 골격만** 구현(서명 생성·검증·리턴 확인 테스트 통과). **공개 콜백 라우트·실 가맹점 자격은 미연동** — 라이선스·법무 확정 후.
> 핵심 원칙: **돈은 후원자/납부자 → PG → 수취 조직(협회) 계좌로 직접.** 우리 플랫폼 계좌를 경유하지 않는다.

## A. 지금 되어 있는 것 / 안 되어 있는 것
| 구분 | 상태 |
|---|---|
| 후원 신청(금액 선택)·매칭·관리 | ✅ 구현·배포 (`/sponsorship/propose`, `/admin/sponsorship`, `/my`) |
| 결제 주문 생성 `createPaymentOrder` | ✅ 코드 있음 (PENDING 생성) |
| VNPay 서명 `vnpaySign`(HMAC-SHA512)·결제URL·리턴검증 `confirmPaymentReturn` | ✅ 어댑터 골격 (`test-payment` 통과) |
| 모의 게이트웨이 `mockPaymentGateway` | ✅ 개발/데모용 |
| **공개 결제 콜백 라우트(return/IPN)** | ❌ 미연동 |
| **실 가맹점 코드·서명키(조직별)** | ❌ 미확보 (라이선스·계약 선행) |
| 환불·분쟁·정산 리포트 | ❌ 미구현 |

## B. 법·제도 선행조건 (베트남)
- **결제중개 서비스**는 베트남 중앙은행(SBV) 인가 사항이다 — **시행령 52/2024/ND-CP**(비현금 결제) 및 관련 회람. 직접 자금을 보관·중개하면 라이선스가 필요하다.
  - **회피 설계**: 우리는 자금을 보관·중개하지 않는다. **PG(VNPay 등)가 수취 조직 계좌로 직접 정산**하고, 우리는 주문·상태·영수증만 기록한다(정보 중개). 이 경계를 문서로 못박아야 한다.
- **가맹점 등록**: 수취 주체(협회/성·시 체육회/종목연맹)별로 PG 가맹점 계약이 필요하다 → **조직별 TMN_CODE·HASH_SECRET**.
- **세무·영수증**: 후원금/등록비의 세무 처리(기부금 영수증 vs 용역 대가) 구분 — 법무·세무 확인.
- **개인정보·현지화**: 결제 관련 개인정보·로그도 베트남 내 저장(시행령 53/2022). 카드 원문은 저장 금지(PG 리다이렉트로 PCI 범위 최소화).

## C. VNPay 연동 절차 (기술)
1. **가맹점 계약** → 샌드박스 자격 → `VNPAY_TMN_CODE`, `VNPAY_HASH_SECRET`, 결제/리턴 URL 수령.
2. **환경변수(.env/시크릿)**: `VNPAY_TMN_CODE`, `VNPAY_HASH_SECRET`, `VNPAY_PAY_URL`, `VNPAY_RETURN_URL`. 조직별로 다르면 매핑 테이블.
3. **결제 시작**: `createPaymentOrder`(주문번호·금액·수취조직) → VNPay 결제 URL 생성(금액 ×100, 서명 `vnpaySign`) → 사용자 리다이렉트.
4. **콜백 라우트(신규 구현 필요)**:
   - `GET /api/payments/vnpay/return` — 사용자 복귀 화면(서명 검증 후 결과 표시).
   - `GET|POST /api/payments/vnpay/ipn` — 서버 간 통지(신뢰 원천). **`confirmPaymentReturn`으로 서명 검증 → 위조/불일치 거절 → 멱등 `markPaid`.** IPN을 정본으로 삼는다(리턴 URL은 UX용).
5. **주문 상태기계**: PENDING → PAID / FAILED / EXPIRED, 재시도·중복 통지 멱등 처리.
6. **정산 확인**: PG가 수취 조직 계좌로 정산했는지 대사(reconciliation) 리포트.

## D. 후원 결제 흐름 (설계)
```
공개 웹: 선수 후원 신청(금액)        →  협회 검토·승인(현재 /admin/sponsorship)
   → 결제 주문 생성(createPaymentOrder, 수취=해당 협회/구단)
   → VNPay 결제(후원자 → PG)
   → IPN 콜백 확정(confirmPaymentReturn → markPaid)
   → 영수증·후원 계약 기록 / 선수·협회 통지
자금: 후원자 → PG → 수취 조직 계좌 (플랫폼 미경유)
```
- 등록비(선수·단체 등록)도 동일 패턴 재사용(`fee_rule` → 주문 → 결제).

## E. 단계별 로드맵 (권장)
1. **샌드박스 PoC** — VNPay 샌드박스 가맹점으로 결제→IPN→markPaid 왕복 검증(콜백 라우트 구현). 실자금 없음.
2. **라이선스·법무 확정** — 자금 미보관 설계 검토, 세무·영수증 방식 확정, 조직별 가맹점 계약.
3. **파일럿** — 소수 협회·종목으로 실결제(소액), 대사·환불·분쟁 절차 검증.
4. **확대** — 전 조직 가맹점 매핑, 리포트·감사 강화.

## F. 결정 필요 (사업 주체)
- 수취 주체 단위(중앙 협회 단일 vs 성·시·종목별 계좌) → 가맹점 구조.
- 결제 수단(VNPay 외 MoMo·ZaloPay·카드 추가 여부).
- 수수료 부담(후원자 vs 수취 조직) 및 표기.
- 후원금 성격(기부 vs 용역) → 세무·영수증.

> ⚠ 이 문서는 **준비/로드맵**이다. 실연동 전까지 공개 화면에 결제창을 노출하지 않는다(미인가 결제 오인 방지).
> ※ 베팅/복권은 결제와 별개이며 **정부 협의 전까지 공개·대외 자료에 미언급**(내부 문서 한정).
