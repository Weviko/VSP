# 21. 빠른 배포 미리보기 (Vercel + Neon)

> 목적: 시스템 **전체를 안정적으로 시연**하기 위한 미리보기 배포. 고정 URL·PC 무관·끊김 없음.
> **데모 데이터만** 올린다(해외 리전). 실제 시민 개인정보를 다루는 **정식 운영은 베트남 리전**으로: [문서 19](19-배포-준비.md).
> 로컬+터널 방식의 한계(RAM/OOM·터널 끊김·로그인 마찰)를 이 배포가 해소한다.

## 전제 (사업 주체 계정)
- **GitHub** 계정 (저장소 1개)
- **Vercel** 계정 (GitHub 연동) — Next.js 자동 빌드·HTTPS
- **Neon** 계정 (관리형 PostgreSQL, 무료 티어) — 또는 Supabase

비밀값은 **각 서비스의 환경변수/시크릿**에만 넣는다. 명령·코드·커밋에 평문 금지.

---

## A. 데이터베이스 (Neon)
1. Neon 프로젝트 생성 → Region은 **Singapore**(가장 가까움).
2. **Pooled connection**(pgbouncer) 문자열을 복사 → 이게 `DATABASE_URL`.
   예: `postgresql://<user>:<pw>@<host>-pooler.ap-southeast-1.aws.neon.tech/<db>?sslmode=require`
   - 서버리스(Vercel)는 요청마다 연결이 늘어 → **반드시 pooled** 문자열을 쓰고 `PG_POOL_MAX=3` 로 낮게 둔다.

## B. 스키마 + 데모 시드 (로컬에서 Neon 대상 1회)
로컬 저장소 루트에 `.env.deploy`(커밋 금지) 를 만들고 한 줄:
```
DATABASE_URL=<A에서 복사한 Neon pooled 문자열>
```
그리고:
```
set -a; . ./.env.deploy; set +a
npm run db:setup       # 스키마·기초 데이터 (마이그레이션 전부)
npm run demo:all       # 조직·전종목 + V.League 데모 스토리
```
→ 완료되면 Neon 에 스키마·데모 데이터가 채워진다. (이 단계는 담당(Claude)이 대신 실행 가능 — `.env.deploy` 만 두면 된다.)

## C. GitHub
```
git remote add origin https://github.com/<계정>/<repo>.git
git push -u origin master
```
(현재 저장소는 커밋돼 있고 원격만 없음. 원격 연결 후 푸시.)

## D. Vercel — 앱 2개로 임포트
같은 저장소를 **프로젝트 2개**로 가져온다(모노레포):

| 프로젝트 | Root Directory | 접속 |
|---|---|---|
| vsp-portal (대외 공개) | `apps/portal` | 로그인 불필요 |
| vsp-platform (업무) | `apps/platform` | 전화번호+OTP |

- Framework Preset: **Next.js** (자동 감지). Install 은 저장소 루트의 npm workspaces 를 자동 사용.
- **환경변수 (두 프로젝트 공통):**
  - `DATABASE_URL` = Neon pooled 문자열
  - `AUTH_SECRET` = 새로 생성한 랜덤 값(두 앱 동일)
  - `PG_POOL_MAX` = `3`
  - `STORAGE_URL` = `file:///tmp/.storage` (첨부는 비영구 — 시연엔 무방. 영구화는 S3)
  - `NEXT_PUBLIC_DEFAULT_LOCALE` = `vi`
- **vsp-platform 에만 추가:** `DEMO_LOGIN` = `1`  ← 이게 있어야 OTP 가 화면에 떠서 로그인 가능
- 1차 배포 후 두 URL 이 나오면, 두 프로젝트에 아래를 추가하고 **재배포**:
  - `VSP_PORTAL_URL` = `https://<portal>.vercel.app`
  - `VSP_PLATFORM_URL` = `https://<platform>.vercel.app`

## E. 로그인 (배포된 업무 앱)
1. `https://<platform>.vercel.app/ko/admin` (또는 `/vi`·`/en`)
2. 전화번호 **`0900000001`** (데모 관리자, SYS_ADMIN) → "인증번호 발송"
3. **화면에 뜬 6자리 OTP** 입력 → 로그인. (쿠키·콘솔 불필요)
   - 다른 데모 계정이 필요하면 `npm run session:mint` 로 세션을 발급하거나, 인물 화면에서 전화번호를 확인한다.

## 검증
- 두 앱 `GET /api/health` → `{"status":"ok","db":true}`
- 포털 `/vi`·`/ko`·`/en` 모두 즉시 렌더(운영 빌드라 언어 전환 즉시)
- 업무 로그인 → `/ko/admin` 진입, 조직·등록/결재·대회·감사 등 클릭

## 주의 (게이트)
- **DEMO_LOGIN 은 미리보기 전용.** 실운영에서는 반드시 끄고 Zalo ZNS(OTP_LOGIN) 로 발송한다 — 켜두면 인증코드가 화면에 노출된다.
- 해외 리전 배포이므로 **데모 데이터만**. 실제 개인정보·정식 운영은 **베트남 리전**(데이터 현지화 시행령 53/2022, [문서 19](19-배포-준비.md)).
- 첨부/증빙 영구 저장은 **S3 호환 스토리지** 필요(`STORAGE_URL=s3://…` + `@aws-sdk/client-s3`).
- **베팅(토토)은 공개·대외 화면·문서에 미언급.**
