# 베트남 스포츠 통합 플랫폼 (VSP) 사업계획서 v1.0

> 작성 2026-09-15 · 이 문서가 **대표 사업계획서**다. 초안(문서 10, v0.9)을 이후 조사(문서 12~16)로 갱신·통합한다.
> 근거 문서: 12 실행계획 · 13 행정시스템 비교 · 14 통합설계 · 15 사이트 실사 · 16 종목구성.

## 1. 요약

**한 문장** — 베트남의 체육 행정(협회 가입·전자결재·전자수납·선수 등록·대회 운영·보조금)과 대중 스포츠 미디어를,
**하나의 데이터 위에 두 얼굴**(내부 행정 전산망 + 외부 스마트폰 웹)로 올린 **베트남 체육의 공식 인프라**를 만든다.

**핵심 근거 (2026-09 실사)**
- 베트남 체육국 사이트조차 **뉴스·정보 수준**이고, 통합 등록·전자결재·회원관리·증명 시스템이 **없다**(문서 15). 최대 종목단체 VFF도, 국가올림픽위 사이트(VOC)도 예외가 아니다.
- 한국은 이 기능들이 **여러 기관에 흩어져 시스템화**돼 있다(g1 등록·KSPO 기금·KADA 도핑…). VSP 는 그 기능을 **하나로 모으고**, 베트남의 빈자리를 채운다. 후발주자라 통합 설계가 가능하다.
- 미디어는 민간·SNS 에 흩어져 있다(도핑기관도 페이스북). VSP 대외 웹이 **공식·통합 스포츠 미디어**를 처음 만든다.

**지금 상태** — 내부 행정 골격(등록·결재·수납·증명·공문·보조금·회원이력)과 외부 웹 기본(종목·일정·순위·선수검색·공시)이 **동작하고, 테스트·빌드를 통과**한다. 남은 것은 문체부 협의로 확정할 세부와 디자인·연동이다.

## 2. 사업 배경과 기회

| | 한국 | 베트남 (현재) | VSP |
|---|---|---|---|
| 선수·지도자·심판 등록 | g1 전자등록·승인 | 없음(카드 신청 링크 수준) | ✅ 등록 + 2단계 결재 |
| 증명서·진위확인 | g1 전자증명서 | 없음 | ✅ |
| 종목단체 관리·공시 | 경영공시 | 없음 | ✅ |
| 대회 운영 | g1 대회정보 | 정보 게시 | ✅ 개최승인·대진·결과 |
| 보조금·기금 | KSPO·e나라도움 | 체육 전용 없음 | ✅ 전주기 |
| 도핑 | KADA 포털 | 페이스북 위주 | 미구현(미팅 후) |
| 대중 미디어 | (민간) 네이버 스포츠 | 분산·SNS | ✅ 대외 웹 |

→ **기회**: 베트남 체육단체 층은 시스템 공백이 크고, 중앙이 표준을 지정하는 **하향식 도입이 현실적**이다(각 단체가 자체 구축할 여력이 없다). 이는 "전 종목 동시 온보딩"을 가능케 하는 이 사업 최대의 지렛대다.

## 3. 무엇을 만드는가 — 구조

### 3-1. 두 얼굴, 세 화면, 하나의 데이터

```
┌── 외부용 · 스마트폰 웹  apps/portal ───────────────  예: vsp.vn
│    네이버 스포츠형. 로그인 없음. 광고 가능. 공개 데이터만 읽음.
│    국민·팬·미디어·후원사
│
├── 내부용 · 행정 전산망  apps/platform ─────────────  예: app.vsp.vn
│    ├ 회원 서비스 /my    선수·지도자·학부모   로그인 · 자기 기록만 · 광고 없음
│    └ 업무      /admin   협회·성시·체육회·문체부  업무 역할 필수 · 광고 없음
│
└── 하나의 데이터
     ├ pub 공개 계층  ← 외부 웹은 여기만 읽는다(읽기 전용 DB 역할)
     └ 원본 계층      ← 내부 행정
```

**설계 제1원칙**: *내부에서 한 번 입력한 데이터가 외부에 자동으로 나타난다.* 홍보를 위해 따로 글을 쓰지 않는다. 두 얼굴을 잇는 것이 `pub` 공개 데이터 계층이다.

### 3-2. 외부용 — 스마트폰 웹 (네이버 스포츠형)

모바일 우선. 네이버 스포츠 동작 실사(문서 14)를 반영한다.

- **머리 3단**: ① 유틸리티(기관소개·체육단체·공시·증명서 확인·언어·로그인) ② **종목 탭(1단)** — 축구·배구·육상·수영·배드민턴·태권도·보비남·농구·e스포츠·전체 ③ 기능 줄 — 일정·결과·순위·선수·뉴스
- **종목 안**(네이버식): 뉴스·영상·일정·순위·기록 → 리그·대회 필터
- **오늘의 경기**: 경기 카드. 상태별 버튼 — 예정=응원, 진행중=중계, 종료=기록. 실시간 점수 갱신.
- **경기 상세**: 응원·라인업·중계·뉴스·영상·기록 탭 + 종목별 기록표 + 팬 한 줄 평
- **개인화(MY팀형)**: 회원이 종목·팀을 구독 → 구독자 수는 인기 지표(후원 중개와 연결)
- **e스포츠 특례**: 데이터로는 한 종목이나, 화면은 **게임 타이틀-우선 내비 + 커뮤니티/중계 강화**(네이버조차 e스포츠는 별도 서비스로 뒀다 — 문서 14)
- 광고는 이 외부 웹에만 둔다.

### 3-3. 내부용 — 행정 전산망 (대한체육회 g1 + 문체부 계열)

협회 사무국(1~5명·모바일 비중 높음)을 전제로 얕고 큰 메뉴.

- **경기인 등록** — 선수·지도자·심판, 동적 서식 + 2단계 결재(법정 처리기한 표시)
- **전자결재·공문 유통** — 기안·합의·접수·문서대장(온나라 계열)
- **전자수납** — 자금은 납부자→PG→협회 계좌 직접(플랫폼 미경유)
- **보조금 전주기** — 공모→교부→집행→정산→검사→공시(e나라도움 계열, 부정 차단 내장)
- **증명서 발급·진위확인**, **회원종목단체 공시**, **대회 개최·운영**
- **회원 서비스(/my)** — 한국 g1 '내 생애주기': 내 등록·성적·신청·납부. 체육인 전자지갑은 확장 검토.

### 3-4. 데이터 경계와 보안 (한국 N²SF 등급 적용)

| 등급 | 데이터 | 누가 |
|---|---|---|
| O 공개 | 경기결과·출생연도·승인된 대회·공시·통계 | 외부 웹(포털 DB 역할) |
| S 민감 | 전화·등록서류·결재·수납·보조금·공문 | 업무 역할 + 본인 |
| C 기밀 | 신분증 해시·건강·징계/도핑·신고자 | 추가 통제(다음 단계) |

- 외부 웹은 `pub` 뷰만 읽는 전용 DB 역할로 접속 → 뚫려도 전화·신분증은 나가지 않는다.
- 권한은 화면·서버액션·API마다 확인(레이아웃만으로 막지 않음). 자동 검사(`check:boundaries`)로 강제.

## 4. 종목 구성 (문서 16)

하나의 종목 = 하나의 국가 종목단체 = 하나의 "폴더". **종목은 코드가 아니라 데이터**(`sort_order`)라 문체부 명단 수령 시 그대로 교체.

- **1군(시연 반영 완료)**: 축구·배구·육상·수영·배드민턴·태권도·**보비남**·농구·**e스포츠**
- **2군**: 탁구·테니스·복싱·유도·레슬링·역도·양궁·사격·펜싱·사이클·조정·체조·핸드볼·트라이애슬론·야구
- **3군**: 펜칵실랏·세팍타크로·우슈·가라테·무에타이·킥복싱·쿠라시·주짓수·체스·샹치·당구·볼링·댄스스포츠·보디빌딩·페탕크·골프·핀수영
- **4군(베트남 전통)**: **다카오·전통무술** — 네이버·한국에 없는 VSP 차별 폴더
- **별도 축**: 장애인체육 — 같은 플랫폼 별도 종목군 vs 분리(미팅 결정)

근거: 베트남 주최 SEA Games 31 = 40종목. 확인 단체: VFF·VFV·VAF·VBSF·VIRESA 등. **VOC 정식 명단은 수령 확정 필요.**

## 4-B. AI 문서 등록 (핵심 방향 · 2026-09-15 착수)

**서류가 올라오면 AI 가 베트남 체육회 공식 폼으로 채우고, 담당자는 전자결재로 승인만 한다.**

흐름: 서류 업로드(PDF·스캔·사진) → **AI 추출** → 공식 폼 초안(항목별 신뢰도 기록) → **사람 검토·확정** → 신청서 제출 + 기존 2단계 전자결재 시작 → 원본 서류가 증빙으로 자동 연결.

원칙(정부 시스템):
- **AI 는 초안만, 최종 결정은 사람.** AI 자동 승인은 없다(감사·책임). AI 가 채우니 담당자는 검토·승인만 — "쉽게 승인".
- **어떤 공식 서식이 와도 붙는다.** 대상은 서식 정의(form_definition)이지 특정 서식 코드가 아니다. 서식이 도착하면 서식 편집기로 등록만 하면 이 파이프라인이 그 서식으로 채운다.
- **추출기는 어댑터.** LLM 사업자·모델이 바뀌어도 호출부는 그대로. 어댑터 연결 전에는 아무것도 지어내지 않고 빈 초안을 만든다.
- 신뢰도 낮은/빈 필수 항목은 검토 대상으로 표시(검토 우선순위).

구현: `core.ingestion_job`(추적) + `ingest.ts`(추출기 레지스트리·ingestDocument·confirmIngestion·검토큐) + 검증 `test:ingest`. **남은 것**: 실제 LLM 추출 어댑터(API 키), 검토·확정 화면, 공식 서식 수령 후 매핑.

## 4-C. 만드는 방식 (수정된 방침 · 2026-09-15)

사업 주체 결정: **파일럿이 아니라 완성본을 먼저 만들고, 미팅에서 바로 쓰며 검토·수정한다.**
- 외부는 **웹사이트(네이버 스포츠형)를 기반**으로 하고 스마트폰에서도 보이는 반응형으로 간다.
- 내부는 위 AI 문서 등록 + 전자결재를 중심으로 완성한다.
- **바뀔 것에 대비**: 베트남 보고·승인 체계는 미팅에서 달라질 수 있으므로, 바뀌는 부분(서식·결재선·권한·보고 양식)은 코드가 아니라 **설정으로 흡수**되게 짓는다. 그래야 미팅 수정이 재작성이 아니라 설정 변경이 된다.

> 참고: 문서 11·12의 "결정 의존 기능은 미팅 후" 원칙과의 관계 — 완성본을 지향하되, 여전히 **설계가 갈리는 것(국가 시스템 연동 방식 등)은 껍데기까지만 만들고 연동부는 설정·어댑터로 비워 둔다.** 헛일을 줄이는 안전장치다.

## 6. 진행 방식 (로드맵 — 문서 12)

| 단계 | 목표 | 완료 기준 | 기간(안) |
|---|---|---|---|
| **P0** | 미팅 준비 | 베트남어 시연 가능 + 서식 요청 발송 | 3~4주 |
| **P1** | 문체부 미팅 | 설계 분기 4개 답변 + 서식·명단 수령 | 1주 |
| **P2** | 구조 확정·IT팀 합류 | 요구 반영(설정으로) + 디자인 적용 | 6~10주 |
| **P3** | 파일럿 (큰 종목1+작은 종목1) | 등록→대회→결과→정산 실데이터 완주 | 8~12주 |
| **P4** | 전국 확산 | 종목별 순차 온보딩 | 6~12개월 |
| **P5** | 공개 플랫폼·후원 중개 | 미디어·랭킹·스폰서십 | P3와 병행 |

**진행 원칙**: 문체부 의견에 따라 바뀔 것은 미리 만들지 않는다. "결정 무관"(결재선 편집기·PDF·권한·베트남어 검수·시연)만 지금, "결정 의존"(공문 세부·위원회·도핑·결제 실연동)은 미팅 후.

**P1 설계 분기 4개**: ① 국가 전자문서시스템 연동 방식 ② 국가 보조금 시스템 유무 ③ 체육 예산 경로 ④ 장애인체육 편입.

## 7. 운영 방식

### 7-1. 인프라·호스팅
- 개발은 인프로세스 DB(PGlite), 운영은 PostgreSQL — `DATABASE_URL` 한 줄 교체, 코드 변경 없음.
- **베트남 국내 호스팅 전제**(사이버보안법·시행령 53/2022). 사업자(Viettel IDC·VNPT·FPT 등)와 부처 지정 클라우드 여부는 법률 자문 후 확정. VOC 사이트조차 불안정한 현실에서 **안정적 운영이 곧 차별점**.

### 7-2. 팀 (P2 기준)
프로젝트 리드1 · 백엔드/풀스택 2~3 · 프론트 2 · 디자이너1 · **베트남 현지 담당 1~2(용어 검수·기관 소통·교육 — 개발자보다 먼저)** · QA1 · 인프라/보안1.

### 7-3. 온보딩·확산
- 하향식: 중앙이 표준 서식·시스템 지정 → 협회는 기준 데이터 입력·교육만.
- 데이터 이관: 기준 데이터(성/시·종목·조직) → 조직→사람→등록 순. 엑셀 일괄 업로드 + 검증 미리보기. 중복은 CCCD 해시로 탐지.

### 7-4. 지원·알림
- 헬프데스크(베트남어), 역할별 교육자료 3종.
- 알림은 **Zalo ZNS**(베트남 표준, 이메일 도달률 낮음). 어댑터만 연결하면 동작.
