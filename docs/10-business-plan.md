# 요약 (Executive Summary)

**한 문장**: 베트남 체육 행정(협회 가입·전자결재·전자수납·대회 운영·선수 등록)과
대중용 스포츠 미디어를 **하나의 플랫폼**으로 통합하여, 베트남 체육의 공식 인프라가 된다.

| 항목 | 내용 |
|---|---|
| 사업명 | Vietnam Sports Platform (코드명 VSP) |
| 시작 경위 | **베트남 측 요청**으로 시작 |
| 목표 지위 | **베트남 체육 공식 시스템 지정** |
| 벤치마크 | 대한민국 대한체육회 (체계) + 네이버 스포츠 (미디어) |
| 범위 | **전 종목 일괄**. 중앙 체육회가 표준 서식을 협회에 지정·강제 |
| 현재 단계 | **동작하는 시스템 구축 완료** (등록·결재·수납·대회·공개 페이지) |
| 다음 단계 | 베트남 문화체육관광부 협의 → 요구사항 반영 → IT팀 확장·디자인 |

### 왜 지금인가 — 세 가지 시점적 이유

1. **베트남에 체육 행정 시스템이 존재하지 않는다.** 선수 등록, 대회 승인, 예산 정산이
   전부 종이와 엑셀로 이루어진다. 만드는 사람이 곧 표준이 된다.
2. **2025년 7월 행정구역이 63개 → 34개로 통합되었다.** 지방 체육 조직이 재편 중이며,
   지금이 새 체계로 데이터를 정리할 수 있는 유일한 시기다.
3. **결제·전자서명 인프라가 성숙했다.** VNPAY·MoMo·전자세금계산서·VNeID가 모두 갖춰져,
   한국이 20년에 걸쳐 만든 것을 단번에 조립할 수 있다.

# 1. 사업 배경

## 1-1. 벤치마크: 대한민국 대한체육회

대한체육회는 60여 년에 걸쳐 체육 행정 체계를 완성했다. 실사 결과 구조는 다음과 같다.

**거버넌스 4층 구조**
```
문화체육관광부 (예산·법령·감독)
  └─ 대한체육회 ── 회원종목단체 약 80개(정회원) + 준회원 4개
        ├─ 시도종목단체 (17개 시도)
        ├─ 시도체육회 → 시군구체육회 (228개)
        └─ 해외한인체육단체
  └─ 국민체육진흥공단 (체육진흥투표권 수익으로 재원 조달)
```

**운영 시스템** (세 개 사이트로 분리)

| 사이트 | 역할 |
|---|---|
| sports.or.kr | 기관 정보·정보공개·경영공시 (기관/사업/데이터 3개 탭) |
| g1.sports.or.kr | 실제 업무 — 경기인등록·증명서·등록현황·대회정보 |
| sports.or.kr/data | 통계 현황판 |

**핵심 업무 흐름 — 경기인 등록**
```
본인인증 → [스포츠인권·도핑방지 교육 이수(필수 선행)] → 신청서 작성
→ ① 시도종목단체 승인 → ② 중앙 종목단체 최종 승인
→ 등록 완료 → 증명서 발급 → 대회 출전 자격
※ 매년 갱신 · 디지털 취약자용 수기 경로 병행
```

**예산·정산 사이클**
```
사업계획서 → 예산 심사 → 교부 → 집행(사업별 전용계좌·구분회계 법적 의무)
→ 실적보고 → 정산 → 감사 → 경영공시
```

> **배울 점**: 정보공개·경영공시가 독립 대분류이고, 등록현황이 대중에 공개되며,
> 증명서 발급만큼 **검증(진위확인)**이 중요하게 다뤄진다.
>
> **고칠 점**: 사이트가 3개로 나뉘어 사용자가 혼란스럽고, 메뉴가 4단계까지 내려가며,
> 모바일 대응이 부족하다. 행정 시스템과 미디어가 완전히 분리되어
> 대중 트래픽이 체육회로 오지 않는다(네이버가 가져간다).

## 1-2. 베트남 현황

**거버넌스**
```
문화체육관광부 (Bộ VHTTDL)
  ├─ 베트남 체육국 (Cục TDTT, 舊 체육총국) — 결정 619/QĐ-BVHTTDL(2025.3.11)
  ├─ 베트남올림픽위원회 (VOC) — 대부분의 국가 종목연맹이 회원
  ├─ 국가 종목연맹·협회 (Liên đoàn / Hiệp hội)
  └─ 성·시 문화체육국 (Sở VHTT) — **2025.7.1부터 63개 → 34개로 통합**
```

**기능 공백 — 실사 결과**

| 기능 | 한국 | 베트남 |
|---|---|---|
| 선수·지도자·심판 통합 등록 | ✅ 온라인 다단계 승인 | ❌ 연맹별 종이·엑셀 |
| 통합 선수 DB·검색 | ✅ | ❌ |
| 전자결재·전자보고 | ✅ | ❌ 공문·직인·우편 |
| 대회 승인·엔트리·기록 | ✅ | △ 오프라인 절차 |

> 베트남은 **"백지에서 통합 설계할 수 있는"** 기회를 갖고 있다.

# 2. 사업 내용

## 2-1. 플랫폼 정의 — 2-Face 구조

```
┌──────────────────── VSP 단일 플랫폼 ────────────────────┐
│                                                         │
│  [공개] 대중용 — 베트남판 네이버 스포츠                   │
│  종목 허브 · 대회 일정/결과 · 선수 프로필 · 통합검색      │
│  뉴스 · 체육단체 · 경영공시 · 통계 현황판                 │
│              ▲ 자동 반영 (별도 편집 작업 없음)            │
│              │                                          │
│  [업무] 협회용 — 베트남판 스포츠지원포털 + e나라도움      │
│  조직·인원 · 경기인등록 · 증명서 · 대회운영               │
│  전자결재 · 전자수납 · 문서 · 보고서                      │
│                                                         │
└─────────────────────────────────────────────────────────┘
  연동: VNeID · VNPAY/MoMo · 전자서명 · 전자세금계산서 · Zalo
```

**설계 제1원칙**: 업무 화면에서 한 번 입력한 데이터는 공개 화면에 **자동으로** 나타난다.
홍보를 위해 따로 글을 쓰는 일이 없어야 한다.

## 2-2. 사업의 핵심 논리 — 선순환 루프

```
협회가 행정 SaaS를 쓴다 (수기 → 전자 전환의 편익)
  → 선수·대회·결과 데이터가 자동으로 쌓인다
  → 대중용 페이지가 인력 투입 없이 채워진다
  → 팬 트래픽 발생
  → 트래픽이 협회의 홍보 채널이 된다 → 협회가 더 열심히 입력한다
  → 스폰서가 붙는다 → 협회에 수익 배분 → 이탈 불가
```

> 네이버 스포츠는 "남이 만든 데이터를 보여주는 회사"이고,
> VSP는 **"데이터를 만들게 하는 도구를 주고, 그 데이터를 보여주는 회사"**다.

## 2-3. Top-Down 강제 모델 (일반 SaaS와의 결정적 차이)

일반적인 스포츠 SaaS는 협회마다 업무 방식이 달라 커스터마이징이 무한대로 늘어나
전 종목 일괄 도입에 실패한다. 그러나 **중앙 체육회가 표준 서식을 지정·강제할 수 있다면**
우리는 협회에 맞추는 쪽이 아니라 **표준을 협회에 배포하는 쪽**이 된다.

| | 일반 SaaS (Bottom-Up) | **VSP (Top-Down)** |
|---|---|---|
| 서식 | 협회마다 다름 → 커스터마이징 지옥 | **중앙 표준 1종 + 종목별 확장 필드** |
| 온보딩 | 협회를 하나씩 설득 | 중앙이 공문으로 지시 |
| 개발 범위 | 협회 수 × 요구사항 | 표준 1벌 |
| 최대 위험 | 협회가 안 씀 | **표준 서식 확정이 늦어지면 전체가 멈춤** |

> ❗ **따라서 이 사업의 최대 병목은 개발이 아니라 "공식 서류 서식 확보"다.**

# 3. 정보구조 (대한체육회 형식 채택) ✅

## 3-1. 공개 영역

```
홈
├─ 종목          종목별 허브 (통계·일정·선수·기록)
├─ 대회          일정(주간/월간/연간) · 대회안내 · 결과
├─ 선수          통합검색(종목·지역·성별·이름) · 프로필 · 랭킹
├─ 뉴스          보도자료 · 영상 · 카드뉴스 · 인물
├─ 체육단체      국가연맹(정회원/준회원) · 성시 체육국 · 경영공시
├─ 공개정보      공지·입찰·채용 · 법령·규정 · 통계 현황판 · 자료실
└─ 소개          조직·임원·연혁 · 공정체육(인권·청렴·신고) · 후원사
```

## 3-2. 업무 영역

```
대시보드
├─ 내 업무       신청 이력 · 활동 이력 · 교육 이력   (한국 '내 생애주기' 대응)
├─ 결재          결재함(법정기한 초과 강조) · 기안
├─ 조직          조직 트리 · 인원/역할 · 경영공시 입력
├─ 인원          통합 인명부
├─ 등록          경기인 등록(6유형) · 승인 · 이적 · 디지털 회원증
├─ 증명서        발급 · 발급이력 · 진위확인
├─ 대회          개최신청 · 참가신청 · 대진 · 경기 · 결과
├─ 수납          요금규칙 · 수납내역 · 미납관리 · 정산
├─ 콘텐츠        기자 자격 승인 · 기사 작성 · 홍보물
├─ 문서 / 보고서  공문 · 정부 제출 보고서
└─ 설정          서식 · 결재선 · 종목/부문 · 권한
```

## 3-3. 한국 대비 의도적 차이

| 항목 | 한국 | VSP | 이유 |
|---|---|---|---|
| 사이트 수 | 3개 | **1개** | 후발주자 이점, 단일 SSO |
| 메뉴 깊이 | 최대 4단계 | **최대 3단계** | 협회 사무국 1~5명, 모바일 중심 |
| 데이터 현황판 | 별도 사이트 | 공개정보 내 메뉴 | 진입 경로 단순화 |
| 기자 기고 | 없음 | **승인 기자 기고** | 콘텐츠 확보 |
| 언어 | 한국어 중심 | **베트남어/영어/한국어** | 국제 노출·한국 파트너 |

| 3 | **수기 → 전자 수납** | ✅ 요금규칙·수납·현금 대리입력·미납 집계 |

# 5. 기술 계획

## 5-1. 아키텍처 ✅

```
apps/web              Next.js 16 · TypeScript · 3개 언어 · 공개 SSG + 업무 SSR
packages/
  core-admin          행정 코어 — 조직·사람·인증·동적폼·전자결재·수납·증명서·감사
  sport-domain        체육 도메인 — 종목·등록·대회·대진·통계·검색
db/migrations         001 코어 · 002 체육 · 003 인증 · 004 콘텐츠
```

**핵심 설계 결정**

| 결정 | 이유 |
|---|---|
| **행정 코어 / 체육 도메인 코드 분리** | 체육에서 검증 후 문화·관광·교육으로 확장하기 위해. 나중에는 불가능한 구조 결정 |
| **하드코딩 금지 (Configuration over Code)** | 서식·결재선·종목·부문·요금이 전부 DB 데이터. **문체부 피드백을 코드 수정 없이 설정 변경으로 흡수** |
| **드라이버 독립 DB 계층** | `DATABASE_URL` 한 줄로 로컬 → NAS → 베트남 서버 이전. 코드 수정 없음 |
| **무제한 깊이 조직 트리** | 2025년 행정구역 개편(63→34) 같은 변동을 데이터로 흡수 |
| **승인자를 사람이 아닌 역할로 지정** | 협회 담당자 교체가 잦음. 사람을 지정하면 그가 떠날 때 결재가 멈춤 |
| **감사 추적 불변 기록** | 정부 감사·법적 분쟁의 증거 |

## 5-2. 하드코딩 금지 원칙의 실체

**상황**: 공식 서식을 받지 못한 상태에서 개발을 시작했다.
**대응**: 서식이 어떤 모양으로 오든 코드를 고치지 않고 수용한다.

| 하드코딩하면 죽는 것 | 데이터로 만든 것 |
|---|---|
| 신청서 항목 | **동적 폼 스키마 엔진** (필드·검증·조건부표시·법정기한) |
| 결재선 | **워크플로 엔진** (단계·승인자역할·조건·위임·SLA) |
| 종목·세부종목·부문 | 종목 테이블 (코드 수정 없이 추가) |
| 요금 | 요금 규칙 엔진 |
| 화면 문구 | i18n 리소스 (vi/en/ko) |

> 체육회가 "이 칸을 추가하고 결재를 3단계로 바꿔라"고 해도
> **관리자 화면에서 설정을 바꾸면 끝난다.**

## 5-3. 자금 흐름 설계 ⚠ (법적 요건)

```
납부자 → PG(VNPAY/MoMo) → 협회 계좌 (직접 입금)
                            ↑ 협회가 PG 가맹점
VSP는 시스템 이용료를 별도 청구 (자금을 보관하지 않음)
```

**이유**: 우리가 받아뒀다가 나눠주면 Nghị định 52/2024상 "수납 대행"이 되어
국가은행(SBV) 결제중개업 라이선스 대상이 되고, 외국 자본에는 사실상 발급되지 않는다.

❓ **확인 필요**: VNPAY 등이 **분할정산(split settlement)**을 지원하는가?
지원하면 "협회비 + 클럽비 동시 결제"가 가능하고, 아니면 별도 결제로 분리해야 한다.

## 6-3. 검증 결과

```
test:schema   마이그레이션 4 + 시드 3 실제 적용, 제약·인덱스·함수 확인
test:dates    date/timestamp/numeric/int 타입 매핑 회귀 방지

test:event    대회생성→개최승인→참가→대진→결과→재생성 안전성→공개 노출 제어

```

**검증 과정에서 발견하고 고친 실제 결함 4건**

| 결함 | 위험 | 조치 |
|---|---|---|
| 트랜잭션 중 다른 커넥션 사용 | 커밋 전 데이터를 못 봄, 간헐적 장애 | 트랜잭션 커넥션 재사용으로 수정 |

| 결제 라이선스 저촉 | 높음 | **해결됨** — 자금이 우리 계좌를 거치지 않는 구조 |
| 데이터 현지화 규제 | 중간 | 법률 검토 필요. 이전 가능한 구조는 확보 |
| 협회 디지털 역량 부족 | 중간 | 오프라인 병행 경로, 현장 교육 인력, 대행 입력 기능 |
| 축구(VFF) 충돌 | 중간 | 행정은 FIFA Connect 연동, **콘텐츠는 직접 서비스** |
| 정부의 직접 운영 회수 | 중간 | 계약에 최소 운영기간·보상·데이터 소유권 명시 |
| 협회 담당자 교체 | 낮음 | **해결됨** — 권한이 역할에 붙음 |
| 행정구역 추가 개편 | 낮음 | **해결됨** — 계층을 데이터로 관리 |
