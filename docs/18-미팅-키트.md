## B. 반드시 확인할 것 (설계가 갈리는 지점)

### B-1. 국가 시스템 연동 (첫 30분 안에)
1. 국가 전자문서시스템(공문축)과 연맹↔문체부 공문을 **어떻게 연동**하나? 우리가 붙나, 문체부 시스템에 우리가 산출물을 넘기나?
2. **대회 개최 신청**은 국가 공공서비스 포털의 행정절차와 겹친다 — VSP 승인 단계는 (a)연맹 내부 사전승인 (b)국가 포털 제출 전 준비 (c)VSP 를 이 절차의 공식 시스템으로 지정 중 무엇인가?
3. 국가 보조금 관리 시스템이 체육 예산에도 쓰이나? 있으면 연동, 없으면 VSP 가 담당.
4. 로그인에 **VNeID** 연동이 가능한가? 필요한 승인 절차는?
5. 체육 통계·보고를 **국가 보고 시스템** 양식으로 넘겨야 하나? 양식·주기는?

### D-0. 데모 준비 · 화면 투어 (심어둔 시나리오)

**준비(미팅 직전 1회):**

```
npm run db:reset && npm run demo:all      # 43종목 + 데모 스토리(축구 V.League 1 2026)
npm run dev:portal    # 대외 웹  http://localhost:3000
npm run dev:platform  # 내부 행정 http://localhost:3001
```

심어둔 스토리: **V.League 1 2026** · 경기 3개(종료 `하노이 2-1 호치민` / 진행중 / 예정) · 팀·득점 순위 · 문자중계 6줄 · 하이라이트 영상 · 뉴스 기사 2 · 후원 가능 선수(Nguyễn Văn Quyết, 팔로워 3) · AI 서류 등록 대기 1건. (`demo:all` 은 멱등 — 이미 있으면 건너뛴다. 다시 심으려면 `db:reset` 부터.)

> 대외↔내부가 **하나의 데이터**임을 보여주는 게 핵심: 내부에서 확정→공개 웹 반영, 미성년은 자동 비공개.

**관리자 화면 빠른 진입 · 스크린샷 캡처:**
- 내부 화면(/admin)은 로그인이 필요하다. 시연·캡처 시 OTP 없이 바로 들어가려면 데모 세션을 발급한다:
  ```
  npm run session:mint      # SYS_ADMIN 데모 세션 토큰 출력
  ```
  출력된 토큰을 브라우저 쿠키 `vsp_session=<토큰>` 로 설정하면 /admin 에 즉시 진입한다. (개발·시연 전용)
- 포트 3000이 다른 앱에 물려 있으면 포털을 다른 포트로: `npx next dev apps/portal -p 3100` (루트에서, `DATABASE_URL=pglite://.pgdata`). 내부는 `-p 3001`. PGlite 단일 프로세스 락 때문에 **한 앱씩** 기동한다.
- 캡처 대상은 위 두 표(대외·내부)의 화면 목록 그대로.

### D-1. 전체 흐름 (완성본으로)

1. 협회 담당자 로그인 → **선수 등록 신청** (서식대로 입력, 첨부)
2. **AI 문서 등록** — 스캔한 신청서를 올리면 AI 가 공식 폼을 채움 → 담당자는 검토·확정만
3. 상급 단체 **전자결재 2단계 승인** (법정 처리기한 표시)
4. 승인 즉시 **외부 웹(공개 선수검색)** 자동 반영 — 만 18세 미만 비공개도 함께
5. **대회 개최 신청** → 10일 법정기한 → 승인 → 대진 자동 생성
6. **보조금** 공모→교부→집행→정산→검사→공시
7. **부정 차단** — 교부액 초과 집행·증빙 중복 제출이 막히는 것
8. **엑셀 내보내기**로 감사 자료 즉시 출력
9. **서식 편집기** — 그 자리에서 항목 하나 추가 → 화면 즉시 반영 (요구 변경을 즉석에서 보여줌)

> 9번이 승부처: "요구가 바뀌면 얼마나 걸리냐"에 **그 자리에서 바꿔 보이는 것**이 답.
