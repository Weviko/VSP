# 13. 행정 시스템 구조 비교와 VSP 구조 결정

> 작성일 2026-09-14 · 선행 문서: 04(청사진) · 09(IA 벤치마크) · 12(실행계획)
> 이 문서는 문서 09 §3-3의 "사이트 수 1개" 결정을 **변경**한다.

---

## 0. 질문과 결론

**질문** — 내부 시스템은 플랫폼 형식으로, 외부는 네이버 스포츠 같은 웹사이트 형식으로 나눠야 하지 않나?

**결론** — 맞다. 조사한 성숙한 체계는 모두 나눈다. 다만 두 가지를 덧붙인다.

1. **얼굴은 셋, 데이터는 하나.** 대외 웹사이트 · 회원 서비스 · 업무 화면. 셋이 같은 DB를 쓴다.
2. **경계는 화면이 아니라 데이터 권한으로 긋는다.** 대외 웹사이트는 공개 데이터 외에는 *읽을 수 없게* 만든다.

한국이 겪은 문제는 "사이트를 나눈 것"이 아니라 **나눈 사이트마다 계정과 데이터가 따로 논 것**이었다.
문서 09가 "1개 사이트"를 택한 이유(중복 로그인·데이터 분산)는 그대로 유효하고, 이번 결정에서도 계정과 데이터는 하나로 유지한다.

## 1. 한국

### 1-1. 정부 일반 — 세 계층

| 계층 | 예 | 누가 쓰나 | 성격 |
|---|---|---|---|
| **정보** (대외) | 부처 홈페이지 (mcst.go.kr) | 국민 누구나 | 비로그인, 공지·정책·공개정보 |
| **서비스** (민원) | 정부24 | 국민 (로그인) | 신청·발급·조회 |
| **업무** (내부) | 온나라시스템 (전자문서) | 공무원 | 결재·공문·기록, **업무망** |

- 공공기관은 약 18년간 **업무망과 인터넷망을 물리·논리적으로 분리(망분리)** 해 왔다.
- 2024년 이후 국가정보원이 **국가 망 보안체계(N²SF)** 를 제시했다. 망을 통째로 가르는 대신 정보를
  **C(기밀) · S(민감) · O(공개)** 로 분류하고 등급에 따라 저장·처리·이동과 보안 통제를 달리한다.
  대부분의 공공 업무 정보는 S, 공개 데이터는 O다.

→ **VSP에 주는 시사점**: 앞으로의 방향은 "망을 나눈다"보다 "데이터 등급으로 통제한다"다. §4-3에서 VSP에 대응시킨다.

### 1-2. 체육 — 대한체육회

| 사이트 | 역할 |
|---|---|
| sports.or.kr | 기관 사이트 (소개·사업·정보공개) |
| **g1.sports.or.kr (스포츠지원포털)** | 경기인 등록·증명서 발급·**내 생애주기**. 2022년 전문체육과 생활체육 신청 서비스를 **통합**하고, 본인인증 방식에서 **회원가입 후 로그인** 방식으로 바꿨다 |
| 내부 업무 시스템 | 협회·체육회 업무 |

2022년 통합 자체가 "따로 논 신청 서비스"를 합친 사례다.

### 1-3. 보조금 — e나라도움

**하나의 시스템, 두 얼굴.** 부처·지자체 담당 공무원은 공모 등록·자격검증·교부결정·집행 모니터링을,
보조사업자(기업·단체·협회)는 공모 검색·신청·교부·집행·정산을 같은 시스템에서 한다.
VSP 보조금 모듈의 `getGrantPerspective()`(주는 쪽/받는 쪽 자동 판단)가 이 구조다.

### 1-4. 미디어 — 네이버 스포츠

네이버 스포츠는 **행정 시스템이 아니다.** 민간 포털이 뉴스·경기·순위·MY팀을 제공하고,
경기 기록은 공식 기록 업체에서 받는다(예: KBO 공식 기록 업체 스포츠투아이, 유료 제공).

**메뉴 구조 — 2026-09-14 브라우저로 직접 확인 (m.sports.naver.com)**

| 줄 | 구성 |
|---|---|
| 1단 · 종목 탭 | 홈 · 야구 · 해외야구 · 축구 · 해외축구 · 농구 · 배구 · N골프 · AG·일반 · e스포츠 · 아웃도어 · **MY팀 설정** |
| 2단 · 기능 줄 | 오늘의 경기 · 승부예측 · 연재 · 이슈톡 · 랭킹 |
| 홈 화면 | 주요 라이브 경기 → 종합 NOW → 숏텐츠 → MY팀 설정 안내 → 바로가기 → AI 추천 뉴스 |

**VSP 대외 웹사이트와의 차이**

| 항목 | 네이버 스포츠 | VSP 현재 | 권고 |
|---|---|---|---|
| 최상위 줄 | **종목 탭**이 1단 | 섹션 줄(홈·일정·결과·순위·선수·뉴스)이 먼저, 종목 탭이 그 아래 | IT팀 디자인 단계에서 **종목 탭을 1단으로** 올린다. 방문자는 종목을 먼저 고른다 |
| 개인화 | MY팀 설정이 종목 탭 줄에 있음 | 없음 | 회원 서비스와 연결해 "내 종목·내 팀" 추가 검토 |
| 홈 첫 블록 | 라이브 경기 | 예정 대회 목록 | 경기 기록 입력이 쌓이면 "오늘의 경기"를 첫 블록으로 |
| 기능 줄의 승부예측 | 있음 | 없음 | 초기 범위에서 제외 (정부 협력 단계) |

생중계가 치지직으로 옮겨 갔다는 내용은 검색 요약으로만 확인했다(상단 서비스 목록에 치지직이 별도 서비스로 있는 것은 직접 확인).

**종목 내부 구조 (2026-09-14 로그인 세션으로 직접 확인)**

종목을 고르면 아래로 하위 메뉴 줄이 열린다. 모든 종목이 **동일한 5개** — 축구·배구·야구 모두 같았다:
> **뉴스 · 영상 · 일정 · 순위 · 포토**  그 아래 리그/대회 필터 칩(예: 주요 경기 · KBO · 야구 기타)

즉 3층: **종목 선택 → 종목 내 기능(뉴스/영상/일정/순위/포토) → 리그·대회 필터.**
- **순위**(종목 안) = 리그 순위·선수 기록. **랭킹**(전역 기능) = "많이 본 뉴스" 인기 순위(날짜별). 둘은 다르다.
- **오늘의 경기**(scoreboard): 날짜별 전 종목 경기 카드 — `[국기]팀 — 점수/상태(예정·종료) — 팀[국기]` + 예정엔 **응원** 배지, 종료엔 **영상** 배지. 베트남 경기도 그대로 나온다.
- **MY팀**: 응원팀을 정하면 그 팀 중심으로 재구성(개인화).

**대한체육회 스포츠지원포털(g1) 상단 (2026-09-14 직접 확인)**
> 내 생애주기 · 경기인 등록 · 증명서 발급 · 등록현황 · S콘텐츠 · 대회정보 · 이용안내

추가로 **체육인 전자지갑**과 **전자증명서 서비스**가 있었다. 이 포털이 "행정·등록"을, 네이버 스포츠가 "대중·미디어"를 맡는다.
확인 방식·근거는 문서 14, 통합 설계도 문서 14.

→ **행정이 데이터를 만들고, 미디어는 그 데이터를 받아 보여준다.** 둘은 다른 시스템이다.

### 1-5. 한국에서 배울 것과 피할 것

| 배울 것 | 피할 것 |
|---|---|
| 정보 / 서비스 / 업무 세 계층 분리 | 사이트마다 다른 계정 |
| 망분리 → 데이터 등급 통제로의 전환(N²SF) | 같은 데이터를 사이트마다 따로 입력 |
| 한 시스템에서 입장별로 다른 화면 (e나라도움) | 미디어가 공식 기록을 유료로만 받는 구조 |

## 3. 베트남 — 국가 시스템이 이미 있다

지난 실행계획(문서 12 §2-3)에서 "베트남에 이미 국가 시스템이 있는지 미팅 첫 30분에 확인하라"고 했다.
공개 자료로 먼저 확인한 결과, **국가기관 층에는 이미 있다.**

| 국가 시스템 | 현황 | VSP와의 관계 |
|---|---|---|
| **Trục liên thông văn bản quốc gia** (국가 공문 유통 축) | 2019년 개통. 당중앙판공실·31개 부처·63개 성시 등 **95개 기관 연결**. 60개 기관은 공유 통합 플랫폼(LGSP), 35개는 문서관리 소프트웨어로 직접 연결 | 한국 온나라에 해당. **국가기관 간 공문은 이미 전자로 오간다** |
| **Cổng Dịch vụ công quốc gia** (국가 공공서비스 포털) | 행정절차 단일 창구. 시행령 59/2022에 따라 **2024.7.1부터 VNeID 계정으로만 로그인**. 2026-09-14 접속 화면의 운영 기관 표기는 **국가데이터센터(공안부)**이고, 이전 절차 페이지 주소는 개편으로 사라졌다. 이 포털은 자동 접근에 봇 검사로 응답하므로 이후 확인은 사람이 직접 한다 | 한국 정부24에 해당. 연동 협의 상대가 정부판공실이 아니라 **공안부 국가데이터센터**일 수 있다 — 미팅에서 확인 |
| **Hệ thống thông tin báo cáo quốc gia** (국가 보고 정보 시스템) | 2020년 개통. 부처·지방 보고 시스템이 연결 | 보고 양식 표준화·자동 집계 |
| **체육 행정절차** | "**Thủ tục đăng cai giải thi đấu, trận thi đấu do liên đoàn thể thao quốc gia hoặc liên đoàn thể thao quốc tế tổ chức**"(국가·국제연맹 주최 대회 개최 절차)가 문화·체육·관광 분야 **51개 전 과정 온라인 공공서비스** 목록에 포함 (2023.12 보도) | **대회 개최 신청은 이미 국가 행정절차다** |

### 3-1. 그런데 체육단체는 국가기관이 아니다

**Liên đoàn thể thao quốc gia(국가 종목연맹)는 "tổ chức xã hội - nghề nghiệp"(사회·직능 단체)** 이다.
국가기관이 아니므로 국가 공문 유통 축에 연결되어 있지 않다. 지방 연맹·클럽·선수는 더 말할 것도 없다.

**→ VSP가 채우는 곳은 "국가 시스템이 닿지 않는 체육단체 층"이다.**
국가기관 층의 시스템을 새로 만드는 것이 아니라, 체육단체 층을 만들고 **경계에서 국가 시스템과 잇는다.**

### 3-2. 경계에서 무엇을 어떻게 잇나

| 업무 | VSP가 하는 것 | 국가 시스템 | 방식 |
|---|---|---|---|
| 연맹 내부 공문, 연맹 ↔ 지방연맹·클럽 공문 | **전부** | 없음 | VSP가 담당 |
| 연맹 ↔ 문체부 공문 | 작성·보관·대장 | 문체부 문서관리시스템 → 국가 공문 축 | **연동** (방식은 미팅에서 확인) |
| **대회 개최 신청** | 서류 준비(요강·경기일정)·연맹 내부 승인·진행 추적 | 국가 공공서비스 포털의 행정절차 | **제출은 국가 포털.** VSP는 서류를 만들어 넘기거나 연동 — **중복 구현 금지** |
| 회원 로그인 | 전화 OTP (현재) | VNeID | **VNeID 로그인 도입 검토** — 국민이 이미 가진 계정 |
| 정부 보고 | 등록·대회·보조금 집계 | 문체부 보고 시스템 → 국가 보고 시스템 | 양식에 맞춘 내보내기 → 연동 |

> ⚠ **확인 필요**: 지금 VSP에 구현한 "대회 개최 승인 결재선(법정 10일)"은 국가 행정절차와 **겹칠 수 있다.**
> 연맹 내부 사전 승인으로 쓸지, 국가 포털 제출 전 단계로 쓸지, 문체부가 VSP를 이 절차의 전문 시스템으로 지정할지 —
> 미팅에서 정해야 한다. 정하기 전에는 이 기능을 더 키우지 않는다.

## 4. VSP 구조 결정

### 4-1. 구조

```
┌─ 대외 웹사이트  apps/portal ───────────────────────────────  예: vsp.vn
│   네이버 스포츠형 — 종목 탭 · 일정/결과 · 순위 · 선수 · 뉴스
│   유틸리티 줄 — 기관소개 · 체육단체 · 경영공시 · 공개정보 · 증명서 진위확인
│   로그인 없음 · 서버 액션 없음 · 광고 가능 · 공개 데이터만 읽는다
│
├─ 업무 플랫폼  apps/platform ─────────────────────────────  예: app.vsp.vn
│   ├─ 회원 서비스  /my     선수·지도자·학부모   로그인 · 자기 기록만 · 광고 없음
│   └─ 업무        /admin  협회·성시·체육회·문체부  업무 역할 필수 · 광고 없음
│
└─ 데이터 (하나)
    ├─ pub 스키마 (O 공개)   ← 대외 웹사이트는 여기만 읽는다 (vsp_portal 역할)
    └─ 원본 스키마 (S·C)     ← 업무 플랫폼
```

### 4-2. 왜 앱은 둘이고 얼굴은 셋인가

| 경계 | 나누는 방식 | 이유 |
|---|---|---|
| **대외 ↔ 공식** | **앱을 나눈다** | 가장 큰 경계다. 광고·트래픽 폭증·검색 최적화·잦은 콘텐츠 변경은 대외 쪽 성질이고, 감사·변경 통제·보안 심사·국내 호스팅은 공식 쪽 성질이다. **정부 공식 시스템에 광고가 붙으면 지정 심사를 통과하기 어렵고**, 후원·광고 수익 모델과 공식 시스템의 인증 범위를 분리할 수 있다 |
| **회원 ↔ 업무** | 같은 앱, **셸과 권한**을 나눈다 | 둘 다 로그인·광고 없음·같은 인증 심사 범위다. 베트남 협회 담당자는 정부망이 아니라 **일반 인터넷**에서 접속하므로 업무 앱을 따로 떼도 망 격리 이득이 거의 없다. 회원 트래픽이 커지면 `/my`를 떼어낼 수 있게 경로로 분리해 두었다 |

### 4-3. 데이터 등급 (N²SF의 C/S/O를 VSP에 적용)

| 등급 | VSP 데이터 | 저장 | 누가 읽나 |
|---|---|---|---|
| **O 공개** | 경기 결과·출생연도·승인된 대회·단체 공시·보조금 공시·집계 통계 | `pub` 뷰 | 대외 웹사이트 (포털 역할) |
| **S 민감** | 전화번호·등록 서류·신청서·결재·수납·보조금 집행·공문 | 원본 스키마 | 업무 역할 + 본인(회원 서비스) |
| **C 기밀** | 신분증 해시·건강 정보·징계/도핑 조사·신고자 신원 | 원본 스키마 | **추가 통제 필요** (다음 단계) |

## 5. 분리 작업 중 발견하고 고친 결함

나누는 과정에서 기존 코드를 전수 점검했고, 다음을 찾았다. **"내부/외부를 나눈다"의 실질이 바로 이 결함들을 막는 것**이다.

| # | 심각도 | 결함 | 조치 |
|---|---|---|---|
| 1 | **치명** | 서버 액션 25개가 권한을 확인하지 않았다. **로그인하지 않은 상태로도** 현금 수납 기록·보조금 교부 결정·서식 활성화·조직 생성을 호출할 수 있었다 (서버 액션은 화면을 거치지 않고 직접 호출되는 공개 종단점이다) | 모든 액션에 업무 역할 확인. 빠지면 테스트가 실패한다 |
| 2 | **치명** | 로그인은 전화번호 OTP만 통과하면 계정이 자동 생성되는데, 업무 화면은 "로그인했는가"만 봤다. **누구든 전화번호로 로그인하면 전체 인원의 전화번호·수납·보조금·공문을 볼 수 있었다** | "업무 역할이 있는가"로 판단. 역할 없는 계정은 회원 서비스로 |
| 3 | 높음 | 업무 엑셀(명단·수납·보조금)도 로그인만 확인했다 | 업무 역할 필요 (403) |
| 4 | 높음 | 종목 홈의 선수 명단에 **만 18세 미만 필터가 빠져** 보호자 동의 없는 미성년 선수 이름이 공개되었다 | 공개 뷰에서 일괄 적용 |
| 5 | 높음 | 선수 프로필 주소에 **아무 사람의 id**나 넣으면 협회 직원·반려된 신청자의 이름·성별·생년·사진이 공개되었다 | 승인된 선수만 공개 뷰에 존재 |
| 6 | 중간 | 반려·대기 중인 등록이 공개 배지로, 반려된 참가 신청이 공개 명단에 표시되었다 | 승인·확정된 것만 |
| 7 | 중간 | 경기 결과표·대진표에 미성년 선수 실명이 나왔다 | 머리글자로 표시 (Nguyễn Văn An → N.V.A.) |
| 8 | 낮음 | 로그인 확인 함수가 Next의 "요청마다 렌더링" 신호를 삼켜 DB 오류로 오인했다 (프로덕션 빌드에서 발견) | 쿠키 읽기를 오류 처리 밖으로 |
| 9 | 낮음 | `db:reset`이 보조금 스키마를 지우지 않았다 | 수정 |

**3·4·5·6·7의 공통 원인**: 같은 공개 규칙을 화면 세 곳이 각자 SQL로 구현했다. 하나는 빠뜨리고 하나는 틀렸다.
→ 규칙을 **DB 뷰 한 곳**(`db/migrations/007_public_views.sql`)으로 옮겼다. 화면을 몇 개 더 만들어도 규칙이 새지 않는다.

### 5-1. 재발 방지 장치

| 장치 | 무엇을 막나 |
|---|---|
| **포털 DB 역할 `vsp_portal`** | `pub` 스키마만 읽을 수 있다. 원본 테이블은 읽기·쓰기 모두 DB가 거절한다. 포털이 뚫려도 전화번호·신분증 해시는 나가지 않는다 |
| **증명서 진위확인은 함수로만** | 뷰로 두면 발급 대상자 전체 목록을 긁어갈 수 있다. 코드 한 건에 한 건만 답하는 함수의 실행 권한만 준다 |
| **`scripts/check-boundaries`** | ① 포털이 공개 데이터 계층 외의 패키지를 import ② 포털에 서버 액션 ③ 공개 데이터 계층이 원본 스키마 조회 ④ 업무·회원 화면에 권한 확인 누락 ⑤ 서버 액션·API에 권한 확인 누락 — 하나라도 있으면 테스트 실패. 일부러 위반 3건을 심어 잡히는 것을 확인했다 |
| **화면마다 권한 확인** | Next 16 인증 가이드: 레이아웃은 화면 전환 때 다시 실행되지 않고 하위 화면 렌더링을 막지 못한다. 그래서 레이아웃이 아니라 화면·액션·API마다 확인한다 |

## 7. 남은 것

### 7-1. 보안 — 다음 단계에서 반드시

| 항목 | 현재 | 필요 |
|---|---|---|
| **조직 범위 권한** | "업무 역할이 있는가"까지만 확인한다. **A 협회 직원이 B 협회의 수납을 기록하는 것은 아직 막히지 않는다** (내부자·감사로그에는 남음) | 액션마다 대상 조직을 확인. 문서 12의 P0 "권한 관리 화면"과 함께 |
| C 등급 데이터 통제 | S와 같은 수준 | 징계·도핑·신고자 정보는 별도 역할 + 열람 기록 |
| 포털 운영 DB 계정 | 역할(`vsp_portal`)은 만들어 두었다 | 운영 배포 시 이 역할의 로그인 계정으로 포털 접속 |

### 7-2. 문체부 미팅에서 확인 (문서 12 §P1에 추가)

1. **대회 개최 행정절차**와 VSP 대회 승인 기능의 관계 — 겹치는가, VSP를 전문 시스템으로 지정할 수 있는가
2. 연맹 ↔ 문체부 공문을 **문체부 문서관리시스템**과 어떻게 잇는가
3. 회원 로그인에 **VNeID** 연동이 가능한가 (필요한 승인 절차)
4. 체육 통계를 **문체부 보고 시스템** 양식으로 넘기는 방법
5. 대외 웹사이트와 업무 플랫폼의 **운영 주체·도메인** — 광고가 붙는 대외 웹사이트를 누가 운영하는가
