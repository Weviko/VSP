# 04. 베트남 스포츠 통합 플랫폼 — 기획 청사진

> 코드명(가칭): **VSP — Vietnam Sports Platform** / `thethao.vn` 급 단일 브랜드 지향

---

## 0. 먼저 짚고 갈 용어 정리 (설계에 직결)

사용자 요구사항의 "결제"는 **두 개의 서로 다른 시스템**이며, 반드시 분리 설계해야 한다.

| 구분 | 한자 | 의미 | 시스템 | 예시 |
|---|---|---|---|---|
| **결재** | 決裁 | 서류 승인/전자결재 | **EAS** (Electronic Approval System) | 사업계획서, 대회개최신청, 선수등록 승인, 예산품의 |
| **결제** | 決濟 | 돈 지불/수납 | **PAY** (Payment System) | 등록비, 대회참가비, 회비, 강습료, 티켓 |

두 시스템은 **연결**된다: "예산 집행 품의(결재) → 승인 → 지급(결제) → 증빙 자동 첨부 → 정산 보고서 자동 생성".
이 연결이 베트남 협회들이 진짜로 원하는 것이며, 한국의 대한체육회조차 완전히는 못 하고 있는 부분이다.

## 1. 플랫폼 전체 구조 (2-Face 아키텍처)

> **2026-09-14 갱신** — 구현에서는 얼굴을 셋으로 나눴다: 대외 웹사이트(apps/portal) · 회원 서비스(/my) · 업무(/admin).
> 대외 웹사이트는 공개 데이터 계층(pub 스키마)만 읽는다. 근거와 해외·베트남 사례는 문서 13.

```
┌───────────────────────────── VSP 단일 플랫폼 ─────────────────────────────┐
│                                                                          │
│   [PUBLIC FACE] 대중용 — "베트남판 네이버 스포츠"                          │
│   · 종목별 홈 · 대회 일정/결과/순위 · 선수 프로필 · 기록실 · 랭킹          │
│   · 뉴스/보도자료 · 영상 하이라이트 · 팬 커뮤니티 · 티켓 · 응원            │
│                        ▲ 자동 발행 (인력 투입 0)                          │
│                        │                                                 │
│   [ADMIN FACE] 협회 업무용 — "베트남판 스포츠지원포털 + e나라도움"          │
│   · 협회 온보딩/멤버십 · 전자결재(EAS) · 전자결제(PAY) · 회계/정산          │
│   · 선수·지도자·심판 등록 · 대회 개최 신청/운영 · 문서함 · 공시             │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
        연동: VNeID · VNPAY/MoMo/ZaloPay · VNPAY-CA(전자서명) · 전자세금계산서
              Zalo OA/SMS 알림 · YouTube/Facebook · Cục TDTT 보고 산출물
```

**설계 제1원칙**: *Admin에서 한 번 입력한 데이터는 Public에 자동으로 나타난다.* 홍보를 위해 별도로 글을 쓰는 일이 없어야 한다.

## 3. 데이터 모델 핵심 (초안)

```
Organization(조직)          — 계층형: Cục TDTT / VOC / 국가연맹 / 성시연맹 / 클럽·팀
  ├─ type, parent_id, sport_id[], tax_code, seal, bank_account
Person(사람)                — 통합 ID (VNeID 연계)
  └─ Role(역할) — person_id × org_id × role_type(선수/지도자/심판/임원/직원) × season
Registration(등록)          — 연도별 등록 신청·승인 상태 (승인 단계 이력 포함)
Sport(종목) / Discipline(세부종목) / AgeGroup / WeightClass  ← 전부 데이터로 관리
Event(대회·행사)            — 승인상태, 요강, 일정, 장소, 주최/주관
  ├─ EventEntry(참가신청) ─ Team/Individual
  ├─ Match(경기) ─ Result(결과) ─ RecordEntry(기록)
  └─ EventBudget(대회 예산) ─ 수입/지출
Document(문서)              — 기안문·첨부·문서번호·보존연한
  └─ ApprovalFlow(결재선) ─ ApprovalStep(단계별 승인/반려/위임)
Payment(결제)               — 주문·수단·상태·영수증·세금계산서·환불
Ledger(회계원장)            — org_id × fund_source(재원) × account_code
Content(콘텐츠)             — 뉴스·보도자료·영상·카드뉴스 (Event/Person과 자동 연결)
AuditLog                    — 전 테이블 변경 불변 기록
```

**멀티테넌시 원칙**: 모든 업무 테이블에 `org_id`를 두고 Row Level Security로 격리. 단, **Public Face용 읽기 뷰는 전 조직 통합** — 이것이 "협회 자체 홈페이지 + 통합 포털"을 동시에 성립시키는 열쇠다.

## 4. 기술 스택 제안 (확정 아님 — 200문답 Q156~175에서 결정)

| 영역 | 1안 (권장) | 근거 |
|---|---|---|
| 프론트 | Next.js (App Router) + TypeScript + Tailwind | SEO(Public Face에 결정적) + SSR + 기존 보유 역량 |
| 백엔드/DB | Supabase(PostgreSQL + Auth + Storage + RLS) 또는 NestJS + Postgres | 멀티테넌트 RLS 적합, 초기 개발 속도 |
| 결제 | VNPAY-QR 1차, MoMo/ZaloPay 확장 | 베트남 표준 |
| 전자서명 | VNPAY-CA 등 CA 연동 | 법적 효력 확보 |
| 인증 | 전화번호 OTP + VNeID(2단계 도입) | 베트남은 전화번호가 기본 ID |
| 알림 | Zalo OA + SMS + 앱 푸시 | 이메일 도달률 낮음 |
| 인프라 | 베트남 리전(VNG/Viettel/FPT Cloud) 또는 AWS ap-southeast-1 + 국내 미러 | 데이터 현지화 규제 대응 |
| 미디어 | CDN + 이미지 최적화, 영상은 YouTube 임베드로 시작 | 초기 비용 절감 |

## 5. 단계별 로드맵

| 단계 | 기간(안) | 목표 | 산출물 |
|---|---|---|---|
| **Phase 0** | 4~6주 | 확정·계약 | 200문답 확정, Cục TDTT/VOC MOU, 파일럿 협회 2~3개 확보, 요구사항 명세서, 법률 검토 |
| **Phase 1 — 등록** | 3개월 | 킬러 기능 | 협회 온보딩, 통합 ID, 선수/지도자/심판 등록 + 다단계 승인, 등록비 결제, 증명서 발급, 협회 홈페이지 자동생성 |
| **Phase 2 — 대회** | 3개월 | 운영 | 대회 캘린더·개최 신청(10일 SLA)·참가 신청·대진·결과 입력, 결과 자동 공개, 실시간 스코어 초기판 |
| **Phase 3 — 결재/회계** | 3개월 | 행정 완결 | EAS 전자결재, 전자서명, 사업계획→예산→집행→정산, 경영공시 |
| **Phase 4 — 미디어/수익** | 3개월 | 성장 | Public Face 고도화, 커뮤니티, 랭킹, 오픈 API, 스폰서십·광고·티켓팅 |
| **Phase 5** | 이후 | 확장 | 학교체육·클럽·장애인체육·e스포츠, 국제 연동, AI |

> 파일럿 전략: **트래픽 큰 종목(축구) 대신, 협조적이고 규모가 적당한 2~3개 종목(예: 태권도·배구·육상)으로 시작**해 완성도를 만든 뒤 축구로 확장하는 것이 성공 확률이 높다.
