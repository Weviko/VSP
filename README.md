# 베트남 체육회 통합 플랫폼 (VSP)

베트남의 체육 행정(협회 가입·전자결재·전자결제·대회 운영·선수 등록)과
대중용 스포츠 미디어(네이버 스포츠 모델)를 **하나의 데이터 위에** 세우는 프로젝트.

얼굴은 셋, 데이터는 하나다 (근거: [문서 13](docs/13-행정시스템-구조-비교.md)).

| 앱 | 주소(개발) | 누가 | 성격 |
|---|---|---|---|
| **대외 웹사이트** `apps/portal` | http://localhost:3000 | 누구나 | 네이버 스포츠형. 로그인 없음. **공개 데이터(pub 스키마)만 읽는다** |
| **업무 플랫폼** `apps/platform` — 회원 서비스 `/my` | http://localhost:3001/vi/my | 선수·지도자·학부모 | 로그인. 자기 기록만 |
| **업무 플랫폼** `apps/platform` — 업무 `/admin` | http://localhost:3001/vi/admin | 협회·성시·체육회·문체부 | **업무 역할 필수** |

## 빠른 시작 (Docker 불필요)

```bash
npm install
npm run db:setup       # 스키마 + 기초 데이터 적용 (인프로세스 PostgreSQL)
npm run demo           # 데모 조직(99)·전종목(43) (선택)

# 터미널 3개
npm run db:serve       # 공유 개발 DB 서버 (두 앱이 같은 DB 를 쓴다)
npm run dev:platform   # 업무 플랫폼  http://localhost:3001
npm run dev:portal     # 대외 웹사이트 http://localhost:3000
```

### 미팅/시연용 완전 데모 (전 화면이 살아 있게)

```bash
npm run db:reset            # 전부 지우고 스키마·시드 재적용
npm run demo:all            # 조직·전종목 + 스토리(대회·경기·순위·중계·영상·기사·후원·투표·광고·AI큐)
npm run rollout:provinces   # 34개 성/시 × 43종목 = 성/시 지부 1,471개 (멱등)
```

- `demo:all` = `demo` + `demo:scenario`. 스토리는 축구 V.League 1 2026(하노이 2-1 호치민)로, 문서 [18 미팅 키트](docs/18-미팅-키트.md) §D 화면 투어와 맞물린다.
- `rollout:provinces` 의 성/시 코드는 **임시**다 — 문체부 공식 34개 코드 수령 시 `scripts/rollout-provinces.mts` 배열만 교체(문서 08).

> **주의 — 개발 DB의 제약**
> 개발 DB(PGlite)는 **파일을 한 프로세스만 열 수 있다.** 두 앱은 `db:serve` 를 거쳐 함께 쓴다.
> `db:serve` 가 떠 있는 동안 `db:setup` / `demo` / `test` 를 실행하면 안 된다.
> 순서: **db:serve 를 끄고 → 스크립트 실행 → 다시 켠다.**
> 이 제약이 불편해지면 Docker PostgreSQL로 전환한다 (`.env.local` 의 `DATABASE_URL` 만 교체).

로그인은 업무 플랫폼에서 전화번호 + OTP로 한다. **OTP는 등록된 알림 어댑터(Zalo ZNS→SMS)로 실제 발송**되며,
운영에서 어댑터가 없으면 로그인이 실패한다(발송 필수 — [문서 19 §D-2](docs/19-배포-준비.md)). **개발 환경에서는 인증번호가 화면에 표시**된다.
남용 방지로 OTP 발급은 번호별 5회/15분·IP별 20회/15분으로 제한된다.
전화번호만 있으면 누구나 계정이 생기므로, **업무 화면은 단체에 업무 역할로 배치된 사람만** 들어간다.
역할이 없는 계정은 회원 서비스(`/my`)로 간다. 실무 운영 방법은 [문서 20 실무 운영 가이드](docs/20-실무-운영-가이드.md).

### 보안 경계 — 새 화면을 만들 때 지킬 것
- 대외 웹사이트는 `@vsp/public-data` 와 `@vsp/web-shared` 만 import 한다. 서버 액션을 두지 않는다.
- 공개 규칙(생년만·미성년 보호·승인된 것만)은 `db/migrations/007_public_views.sql` 한 곳에 있다. 화면에서 다시 구현하지 않는다.
- 업무 화면은 `requireWorkspace(locale)`, 회원 화면은 `requireMember(locale)`, 서버 액션·API는 `workUserOrNull()` 을 **화면·함수마다** 부른다. 레이아웃에서만 막으면 안 된다 (App Router는 화면 전환 때 레이아웃을 다시 실행하지 않는다).
- 운영에서 대외 웹사이트는 `vsp_portal` 역할의 로그인 계정으로 DB에 접속한다.
- 위 규칙은 `npm run check:boundaries` 가 검사하고, `npm test` 에 포함되어 있다.

### 데이터베이스 전환
`DATABASE_URL` 한 줄만 바꾸면 된다. **코드 수정은 없다.**

| 환경 | 값 |
|---|---|
| 개발 (기본) | `pglite://.pgdata` — 인프로세스 PostgreSQL, 설치 불필요 |
| Docker | `postgresql://vsp:vsp_dev_pw@localhost:5432/vsp` (`npm run db:up`) |
| NAS / 베트남 서버 | 해당 서버의 접속 문자열 |

PGlite는 WASM으로 컴파일된 실제 PostgreSQL이라 같은 SQL이 그대로 돈다.

### 환경변수 (`.env` · 예시는 `.env.example`)

키·비밀번호는 **명령/설정에 평문으로 쓰지 않고** `.env` 로만 주입한다.

| 변수 | 쓰임 |
|---|---|
| `DATABASE_URL` | DB 접속 (위 표) |
| `STORAGE_URL` | 첨부 저장소. 기본 `file://.storage` (개발·NAS), 운영은 `s3://…` |
| `VSP_PORTAL_URL` / `VSP_PLATFORM_URL` | 두 앱이 서로를 링크할 주소 (기본 3000/3001) |
| `AUTH_SECRET` | 세션 서명 키 (운영에서 반드시 교체) |
| `VSP_LLM_API_KEY` *(선택)* | AI 서류 추출기 키. 있으면 LLM 추출기(스캔·PDF·산문), 없으면 텍스트만 옮기는 안전 기본 추출기로 폴백 |
| `VSP_LLM_MODEL` / `VSP_LLM_BASE_URL` | LLM 모델·엔드포인트 (사업자·모델은 문체부 협의 후 확정) |

**AI 서류 추출기 교체**: 키 한 줄만 넣으면 어댑터가 자동 전환된다(`apps/platform/src/lib/adapters.ts`). 어느 쪽이든 AI는 초안만 만들고, 사람이 확정해야 전자결재가 시작된다(자동 승인 없음).

## 검증

```bash
npm test              # 아래를 모두 실행
npm run test:schema   # 마이그레이션·시드를 실제 PG 엔진에 적용하고 제약까지 확인
npm run test:dates    # 날짜가 문자열 그대로 오는지 (시간대 때문에 하루 밀리는 사고 방지)
npm run test:bracket  # 대진 생성기 (토너먼트·리그)
npm run test:smoke    # 조직→로그인→신청→2단계 결재→승인까지 전 흐름
npm run test:event    # 대회 개최 승인→참가 접수→대진→결과 기록
npm run test:forms    # 서식 편집기 (버전·활성화·검증 반영)
npm run test:grant    # 공모→교부→재교부→집행→정산→검사→공시
npm run test:infra    # 파일 저장·엑셀 내보내기·알림
npm run test:attach   # 첨부가 실제로 저장되고 남의 첨부는 붙지 않는지
npm run test:ingest   # AI가 서류를 공식 폼으로 채우고, 사람이 확정해야 결재가 시작되는지
npm run test:llm      # LLM 추출기 어댑터 (프롬프트 구성·응답 파싱·키 폴백, 네트워크 없이 모의 호출)
npm run test:import   # 인물 엑셀 일괄 등록 · 사람 검색 선택기 · 인물 조회/수정/비활성(CRUD)
npm run test:org-import   # 조직 엑셀 일괄 등록 (상위 참조·위상 정렬)
npm run test:otp      # OTP 발송 판정 (템플릿·즉시발송·개발용 구분·미설정 예외)
npm run test:zalo     # Zalo ZNS 알림 어댑터 (템플릿 매핑·정규화·발송·오류판정)
npm run test:payment  # 결제 게이트웨이 골격 (VNPay 서명 생성/검증·변조탐지·모의)
npm run test:i18n     # 세 언어(vi/en/ko) 키 정합 · 정적/동적 t() 키 존재 가드
npm run test:public   # 대외 웹사이트가 공개 규칙을 벗어난 데이터를 읽을 수 없는지 (포털 DB 역할로 실행)
npm run check:boundaries  # 포털 import 제한 · 화면/액션/API 권한 확인 누락 검사
```

> `npm test` 는 `verify-schema` 로 **DB를 비우고** 재적용한다. 시연 데이터가 필요하면 테스트 후
> `npm run db:reset && npm run demo:all && npm run rollout:provinces` 로 다시 심는다.

> PGlite는 파일 잠금을 한 프로세스만 쥘 수 있다.
> `db:serve` 를 켜 둔 채로는 스크립트가 돌지 않는다 — 멈추고 실행한 뒤 다시 켠다.

## 구조

```
apps/
  portal/              대외 웹사이트 — Next.js 16 · vi/en/ko · 네이버 스포츠형 · 공개 데이터만
  platform/            업무 플랫폼 — 회원 서비스(/my) + 업무(/admin) · 로그인 필수
packages/
  core-admin/          행정 코어 — 조직·사람·인증·동적폼·전자결재·결제·공문·보조금·감사
  sport-domain/        체육 도메인 — 종목·등록·대회·대진 생성기
  public-data/         공개 데이터 계층 — pub 스키마만 조회 (대외 웹사이트의 유일한 데이터 통로)
  web-shared/          두 앱이 함께 쓰는 화면 부품·번역
db/migrations/         001 코어 · 002 체육 · 003 인증 · 004 콘텐츠 · 005 공문 · 006 보조금 · 007 공개뷰 ·
                       008 AI등록 · 009 경기상세 · 010 순위판 · 011 구독(MY팀) · 012 후원 ·
                       013 경기콘텐츠(중계·영상·뉴스뷰) · 014 팬참여(투표·응원) · 015 광고 · 016 증명서 취소
db/seed/               역할·조직단계·시즌 / 등록서식·결재선 / 기자·광고지면 / 기사검수 결재선(004)
scripts/               db-setup · demo-data · demo-scenario(시연 스토리) · rollout-provinces(성/시 본등록) ·
                       검증 스크립트(test-*) · 구조 경계 검사(check-boundaries)
docs/                  분석·결정 문서 (01~20)
```

**핵심 설계 원칙**: 행정 코어와 체육 도메인을 코드 레벨에서 분리한다.
체육에서 검증한 뒤 문화·관광·교육 등 다른 행정 분야로 확장하기 위해서다.

## 백업·복구

| 환경 | 백업 | 복구 |
|---|---|---|
| 개발 (PGlite) | `.pgdata/` 디렉터리를 통째로 복사(앱·`db:serve` 정지 후). 첨부는 `.storage/` | 복사본을 되돌려 놓고 재기동 |
| Docker/운영 (PostgreSQL) | `pg_dump`(스키마+데이터). 첨부는 저장소(S3 버킷) 스냅샷 | `pg_restore` |

- 데이터 현지화(시행령 53/2022): 운영 DB·첨부는 베트남 내 서버/리전에 둔다.
- 감사 원장(`core.audit_log`)은 삭제하지 않는다 — 모든 변경 이력이 여기 쌓인다.
- 스키마는 마이그레이션이 원본이다. 완전 재구축: `npm run db:reset` → (필요 시) `demo:all` → `rollout:provinces`.

## 현재 단계

**완성본(pre-미팅).** 구조·기능·데이터·다국어·테스트·대규모 성능까지 검증된 상태로, 문체부 협의 전 100% 구현을 목표로 만들었다.

**대외 웹사이트**: 홈 · 종목 허브 · 경기(스코어보드) · **경기 상세(기록·라인업·문자중계·뉴스·영상 탭)** · 대회 일정·결과 ·
순위판(팀/개인) · 선수 통합검색·프로필 · 체육단체 디렉토리(성/시 필터)·경영공시 · 통계 현황판 · 증명서 진위확인 ·
**뉴스·기사** · **후원 쇼케이스** · **팬 투표·응원(결과 표시)** · **광고 지면**

**업무 플랫폼**: 조직·인원(**조회·수정·비활성 + 엑셀 일괄 등록**) · 등록(자격검증·승인/반려) · **시즌(연간 회기)** · 증명서 ·
대회(승인·엔트리·대진·결과) · 전자결재 · 수납(요금 규칙)·보조금 · 공문함 ·
**AI 서류 등록(추출→검토→확정→결재)** · **콘텐츠(기사 작성·검수·결과 자동기사·기자 자격)** ·
**경기 콘텐츠 작성(중계·영상)** · **팬 투표 관리** · **광고 지면 관리** · **알림 큐 운영** · **감사 로그 뷰어** ·
설정(동적 서식) · 회원 서비스 `/my`(이력·구독·후원) · 헬스체크 `GET /api/health`(두 앱)

**안전 원칙**: 대외/업무 데이터 분리(pub 스키마 + `vsp_portal` 역할) · 미성년 보호·출생연도만 공개 · AI는 초안만(사람 확정) ·
후원/광고는 플랫폼이 자금 경유 안 함 · 베팅은 공개·대외 문서에 미언급.
